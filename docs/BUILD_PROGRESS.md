## 1. 오늘까지 완료한 작업

### 프로젝트 기반

- Next.js 16, TypeScript, Tailwind, shadcn/ui 기반 프로젝트를 만들었다.
- 업무별 폴더와 공통 UI 폴더를 준비했다.
- Git 저장소와 원격 저장소를 연결했고, Vercel 프로젝트도 연결했다.
- Local 우선 원칙에 따라 Preview 검토와 환경 분리는 아직 보류 중이다.

### 로그인과 외부 서비스 연결

- Clerk Development 로그인·로그아웃을 연결했다.
- 로그인하지 않은 사용자는 업무 화면으로 들어갈 수 없게 했다.
- Supabase Dev 프로젝트를 연결했다.
- Vercel 환경 변수 이름을 등록했지만, Production용 Clerk·Supabase 환경은 Dev와 분리해 추후 설정해야 한다.

### 승인 디자인의 코드 구현

승인된 `docs/Design_guide` 시안을 Next.js 화면으로 옮겼다. 모든 화면은 가공 예시만 표시하며 실제 DB 저장은 하지 않는다.

| 화면 | URL | 현재 상태 |
|---|---|---|
| 대시보드 | `/dashboard` | 현황 카드, 오늘 할 일, 최근 매물 예시 구현 |
| 매물 목록 | `/listings` | 검색·필터 모양, PC 표, 모바일 카드 구현 |
| 신규 매물 등록 | `/listings/new` | 건물 → 호실 → 조건 입력 3단계 UI 구현 |
| 매물 상세 | `/listings/[listingId]` | 정보 요약, 상태, 연결 업무 탭, 민감 정보 기본 숨김 구현 |
| 상담 관리 | `/consultations` | 현황 카드, 필터, 상담 목록 구현 |
| 계약 관리 | `/contracts` | 만기 안내, 현황 카드, 계약 목록 구현 |
| 광고 관리 | `/advertisements` | 채널 현황, 문구 템플릿 선택·복사 구현 |

### 디자인 시스템·구조 정리

- 디자인 가이드의 Inter 본문 글꼴과 Roboto Mono 숫자 글꼴을 공통 적용했다.
- 시안의 배경·카드·경계선·브랜드 파랑 색상을 공통 디자인 토큰으로 적용했다.
- 페이지는 조립만 담당하고, 화면 전용 UI는 `features/<업무>/components/`, 여러 화면이 함께 쓰는 UI는 `components/shared/`로 분리했다.
- `AppShell`, `PageHeader`, `MetricCard`, `StatusBadge`, `SensitiveInfo` 공통 부품을 만들었다.
- 사이드바와 상단 헤더를 승인 시안의 메뉴 문구와 아이콘 체계에 맞췄다.
- 상단의 신규 매물 등록 버튼은 대시보드에만 표시되도록 수정했다.

### 빌드 시작용 수동 스킬

- `skills/realestate-build/SKILL.md`를 만들었다.
- 수동 실행 시 `AGENTS.md`, 작업 현황, TODO와 작업 종류별 필수 문서를 먼저 읽고 구현 범위·보안 규칙·검증·문서 갱신 순서로 진행하도록 정리했다.
- 스킬 형식 검증을 통과했다.

### Dev DB 구조 작성 — 아직 적용하지 않음

아래 SQL 파일은 검토·승인 후 Dev Supabase에 적용할 준비만 되어 있다. **현재까지 실제 실행하지 않았다.**

| 파일 | 준비된 내용 |
|---|---|
| `supabase/migrations/0001_create_organizations_and_members.sql` | 조직, Clerk 사용자 멤버십, admin/staff, active/inactive |
| `supabase/migrations/0002_create_buildings_units_and_listings.sql` | 건물 → 호실 → 매물, 중복 방지, 현재 매물 1건 제한, 금액·날짜 검사 |

자세한 적용 대기 내용은 `docs/DEV_DB_SCHEMA_PENDING.md`에서 확인한다.

## 2. 확인 완료 상태

- 코드 규칙 검사(`lint`)는 디자인 구현 작업마다 통과했다.
- Clerk 로그인 보호와 Local 업무 화면 접근을 확인했다.
- 실제 데이터는 입력하지 않았다.

아직 완료로 판단하지 않은 항목:

- 전체 빌드는 Windows의 설치 라이브러리 파일 접근 제한 문제로 재확인이 필요하다.
- Preview 화면 검토와 Local·Preview·Production 환경 분리는 보류 상태다.
- admin/staff/비활성/다른 조직 권한 검증은 멤버십·RLS 구현 후 진행한다.

## 4. 반드시 지킬 기준

- 일반 매물 수정은 기존 현재 매물을 수정하며 새 매물을 자동 생성하지 않는다.
- 계약 완료·취소는 매물 상태를 자동 변경하지 않고 사용자가 확인한다.
- 광고 문구 템플릿 사용만으로 광고·매물 상태를 자동 변경하지 않는다.
- 민감 정보는 목록에서 숨기고 상세 흐름에서 필요한 경우에만 표시한다.
- DB migration은 먼저 파일로 작성하고, 사용자 승인 뒤 Dev → Preview → Production 순서로 적용한다.
- Production 실제 데이터는 RLS·조직 분리·수용 테스트가 모두 끝난 뒤에만 입력한다.
