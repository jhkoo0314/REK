- 매물 화면의 임시 `계약 완료` 동작은 브라우저에서 정상 확인했지만, Streamlit 기준과 맞지 않아 P1 계약관리 구현 시 제거한다. 계약 진행·완료는 계약관리에서만 처리하고, 계약관리의 확정 결과가 매물을 `contract_complete`·`is_current = false` 과거 이력으로 전환하도록 이관한다. 기존 계약 완료 Dev 테스트 매물을 같은 기준으로 정리하는 `20260826000900` migration은 수동 적용 대기다.
- Streamlit 기준으로 P1 계약 관리의 자동 반영 규칙을 확정했다. 계약 진행·잔금 예정은 연결 매물을 계약 진행으로, 계약 완료는 과거 이력으로, 해지·만료는 아직 계약 진행인 매물만 공실로 되돌린다. 계약 일정 날짜 자체는 상태를 자동 변경하지 않는다.
- 계약은 매물과 같은 거래 방식(월세·전세·매매·확인 필요)과 별도 계약 구분(신규 계약·재계약)을 저장하도록 정리했다. 새 계약에서 실제 계약 매물을 고르면 거래 방식이 자동 입력되며, 등록·상세·수정 화면 모두 같은 문구를 사용한다. 이를 위한 `20260826001700_split_contract_transaction_and_kind.sql`은 Dev DB 수동 적용 대기다.
- 현재 매물 상세에 `관리 종료` 확인창을 추가했다. 실제 삭제 대신 `타 부동산 계약` 또는 `기타` 사유를 선택해 `ended` 상태·`is_current = false`로 전환하고 과거 이력을 보존하며, 새 매물 등록 가능과 기록 보존 영향을 먼저 설명한다. 사용자가 Dev DB 적용과 브라우저 흐름을 정상 확인했다. P1 상담·계약 연결 구현 전이라 연결 건수 표시는 없다.
- 신규 호실에 `302호` 같은 숫자 호실을 입력하면 층을 자동 제안하고 직접 수정할 수 있게 했다. 호실 단계의 방 구조 입력은 제거했으며, 현재 매물 조건의 방 구조로 표시·조회한다. 현재 선택 가능한 방 구조는 원룸·투룸·투베이·쓰리룸·주인세대다.
- 위 추가 방 구조를 Dev DB에도 저장할 수 있도록 `20260826000500_expand_residential_property_types.sql`을 작성했다. 이 파일은 아직 Dev에 적용하지 않았다.
- P1 상담의 데이터·저장 규칙을 구현했다. `20260826001100_create_p1_consultations.sql`에는 일반/매물 상담, 고객 연락처, 복수 희망 조건, 상담 상태·진행 단계, 후속 이력과 최신 요약 재계산 trigger를 넣었다. Dev에서는 RLS를 명시적으로 비활성화하고 가공 데이터용 접근 권한만 부여한다. 파일만 작성했으며 Dev DB에는 아직 적용하지 않았다.
- 새 상담 등록은 실제 DB 저장 화면으로 교체했다. 같은 조직의 현재 매물만 최초 문의 매물로 연결하며, 고객 연락처는 상담 화면에서만 저장·표시할 준비를 했다. 후속 이력의 추가·수정·삭제 서버 처리도 조직 확인 뒤 동작하도록 준비했으며, 목록·상세 타임라인 UI는 다음 3-2 단계에서 연결한다.
