# 디자인·구현 협업 규칙

## 역할

- Gemini: 정적 디자인 시안·톤·레이아웃 제안만 한다. 코드·DB·환경변수·실제 데이터를 바꾸지 않는다.
- Codex: 승인된 디자인을 Next.js 코드로 구현하고, 권한·DB·테스트·문서를 관리한다.
- 사용자: 디자인과 업무 규칙의 중요한 변경, Dev DB 적용, Production 전환을 승인한다.

## 재빌드 방식

1. `TODO.md`의 현재 단계와 `REBUILD_MASTER_SPEC.md`를 확인한다.
2. 디자인 가이드에서 재사용할 공통 부품과 화면 전용 부품을 정한다.
3. Codex가 코드로 구현한다. Gemini 결과를 파일에 직접 덮어쓰지 않는다.
4. 정상·오류·빈 화면·권한 없음·모바일을 확인한다.
5. 완료 내용과 검증 결과를 `BUILD_PROGRESS.md`에 기록한다.

## 금지

- 실제 고객·계약·출입 정보를 시안·Dev·Preview에 사용하지 않는다.
- 디자인 편의를 위해 업무 흐름·민감 정보 보호·조직 분리 규칙을 바꾸지 않는다.
- 승인 없이 DB migration 적용·RLS 변경·배포·Git push를 하지 않는다.
