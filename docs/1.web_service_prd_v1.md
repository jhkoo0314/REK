## 목적

현재 Streamlit 내부 업무 도구를 로그인 기반 웹으로 다시 구현한다. 고객 공개 사이트가 아니며, 초대된 사무실 직원이 매물·상담·계약·광고비·오늘 할 일을 처리하는 도구다.

## 성공 기준

1. 직원이 건물 → 호실 → 매물을 중복 없이 등록·검색·수정한다.
2. 일반 수정은 현재 매물만 바꾸며 연결 기록을 보존한다.
3. 상담 후속 연락과 계약 일정을 오늘 할 일에서 확인한다.
4. 매물 목록·오늘 예정 업무에서는 연락처·비밀번호·내부 메모를 보이지 않는다. 단, 상담 관리는 후속 연락 업무를 위해 같은 조직의 로그인 직원에게 고객 연락처를 기본 목록에서 표시한다.
5. 가공 계정 권한과 Production RLS 확인 뒤에만 실제 업무를 시작한다.

## 기능 범위

| 우선 | 포함 기능 |
| --- | --- |
| P0 | 로그인, 조직·멤버, 건물·호실·매물 등록/검색/상세/수정, 제한 연락처·호실 출입 정보의 상세 관리, 사진 보유 여부·재확인·현장 상태·보유처, 빠른 수정, 이력 확인 |
| P1 | 일반/매물 상담·후속 이력·고객 연락처·희망 조건·집중 대응, 계약·단계 이력·출처 상담, 오늘/지연 업무·완료 체크, 월별 플랫폼 광고비, 매물 유형별 광고 문구 템플릿 |
| P2 | 권한·모바일·Preview·Production RLS·운영 수용 검증 |

## 제외 범위

- 사진 파일 업로드, OCR, 대량 수정
- 매물별 광고 채널·외부 광고 등록·성과 분석, Excel·CSV 내보내기
- 자동 문자, AI 자동 작성, 고객 공개 화면
- 기존 Streamlit SQLite 실제 데이터 자동 이관

## 향후 매물 종류 확장

초기 운영은 원룸·투룸 중심이다. 그러나 매물 종류 구분과 공통 정보는 아파트·오피스텔·상가·사무실까지 고려해 설계한다. 각 종류의 전용 입력(예: 아파트 동·단지, 상가 권리금)은 실제 사용을 결정한 뒤 별도 승인·migration·화면 작업으로 추가한다.

## 핵심 업무 규칙

- 일반 조건 변경은 새 매물을 만들지 않고 현재 매물을 수정한다.
- 계약의 실제 계약 매물과 출처 상담의 최초 문의 매물은 달라도 된다.
- 계약 진행·완료·해지·만료는 계약관리에서만 처리한다. 계약 상태 또는 단계 이력 저장이 연결 매물 상태를 정해진 규칙으로 반영하며, 계약 완료 시 출처 상담을 종료하고 다음 연락을 해제한다.
- 광고비는 월별 플랫폼 총액만 기록해 향후 가성비 분석의 기준 자료로 쌓는다. 현재는 매물·상담·계약과 자동 연결하거나 성과를 계산하지 않는다.
- 광고 문구는 유형별 읽기 전용 기본 템플릿을 선택해 확인한 매물 값만 넣고 복사한다. 매물 상태는 바꾸지 않으며, 사무실 공용 템플릿 관리는 제공하지 않는다.
- Excel·CSV 다운로드는 MVP에서 제공하지 않는다. 민감정보 열람·자료 반출 제한은 admin 중심의 후속 보안 작업으로 다룬다.
- 개발·검토 환경에는 가공 데이터만 사용한다.
