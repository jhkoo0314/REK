# 사용자 접근·권한 정책

## 역할

| 역할 | 권한 |
| --- | --- |
| admin | 사무실 업무 전체 처리, 멤버 관리·비활성화 |
| staff | 매물·상담·계약·오늘 할 일·광고비 업무 처리 |
| inactive | 로그인해도 업무 데이터 접근 불가 |

## 공통 정책

- 로그인은 Clerk로 처리한다.
- 서버는 Clerk 사용자와 활성 `organization_members`를 확인한다.
- 업무 데이터에는 모두 `organization_id`를 둔다. 브라우저가 보낸 조직 ID는 신뢰하지 않는다.
- 기본 시작 화면은 상담 관리(`/consultations`)다.
- 다른 조직·비활성·미로그인 사용자는 업무 데이터를 읽거나 바꿀 수 없다.

## 민감 정보

- 연락처는 `building_contacts`, 출입 비밀번호와 출입 메모는 `unit_access_details`에 분리해 저장한다.
- admin과 active staff는 **자기 조직의 건물·호실 상세 화면에서 사용자가 직접 열람할 때만** 제한 정보를 볼 수 있다. inactive·멤버 없음·다른 조직 사용자는 볼 수 없다.
- 기본 매물 목록·빠른 검색·오늘 예정 업무·일반 내보내기·광고 문구·목업 데이터에는 포함하지 않는다.
- 연락처·출입 비밀번호를 매물 표의 열, URL, 알림 문구, 브라우저 로그에 넣지 않는다. Production 전환 시 별도 RLS 정책과 열람 기록 필요 여부를 확인한다.
- 단, `consultations`의 고객 연락처는 후속 연락을 위한 업무 정보이므로 같은 조직의 active admin·staff에게 상담 기본 목록과 상세에서 표시한다. 매물·대시보드·오늘 예정 업무·광고·일반 매물 Excel에는 표시하지 않는다.

## 확인 기준

- [ ] admin과 staff가 자기 조직 업무를 처리한다.
- [ ] inactive와 멤버 없음 계정이 차단된다.
- [ ] 다른 조직 ID를 주소에 넣어도 데이터를 볼 수 없다.
- [ ] admin·staff가 자기 조직의 상세에서만 제한 정보를 열람할 수 있고, 기본 목록·내보내기에는 나오지 않는다.
- [ ] 상담 기본 목록의 고객 연락처는 같은 조직의 active admin·staff에게만 보이고, 다른 업무 목록·다른 조직에는 보이지 않는다.
