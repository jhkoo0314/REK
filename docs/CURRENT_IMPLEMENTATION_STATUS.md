# 현재 구현 상태

> 최종 갱신: 2026-08-26
>
> 이 문서는 “실제로 구현·확인한 것”만 기록한다. 계획이나 작성 예정 migration은 완료로 적지 않는다.

## 현재 단계

- 0-A 단계 진행 중 — 가공 목업 데이터 기반의 전체 업무 화면과 주요 화면 전환 구현 완료
- 다음 작업: 실제 브라우저에서 로그인·모바일·가공 데이터 흐름을 확인하고, 오류·저장 중·권한 없음 공통 상태를 보완

## 현재 구현된 기능

- Next.js 16·TypeScript·Tailwind 프로젝트를 루트 폴더에 만들었다.
- Clerk Development를 연결하고, 로그인·회원가입 주소와 사용자 메뉴를 추가했다.
- 로그인된 사용자만 업무 화면 그룹에 접근하도록 했다. 기본 시작 주소는 `/consultations`다.
- 공통 `AppShell`, `PageHeader`, 빈 화면 부품과 상담·인박스·매물·건물·계약·광고의 빈 주소를 기능별 파일로 만들었다.
- 가공 목업 데이터로 상담 목록·상세·상담 조건 매물 검색·제안 화면 이동, 업무 인박스, 건물·호실 탐색기, 계약 목록, 광고비·문구 화면을 구현했다.
- 실제 DB 조회·저장, Supabase 연결, migration은 아직 구현하지 않았다.

## 문서·설정 상태

- 재빌드 범위, 폴더 구조, 단계별 TODO, 1~13 기준 문서를 새 기준으로 정리했다.
- 화면 컨셉을 목록 중심 부동산 업무 CRM으로 확정했다. 상담 관리는 대표 화면·로그인 후 시작 주소(`/consultations`)이며, 매물 관리는 상담에 제시할 재고 관리로 둔다. 업무 인박스는 작은 보조 화면이다.
- Supabase 원격 설정과 Clerk 원격 설정은 보존했다.
- Dev DB 초기화, 새 migration 작성·적용, RLS 변경, 배포는 하지 않았다.

## 다음 작업과 승인

1. 실제 브라우저에서 로그인·모바일·가공 데이터 화면 흐름을 확인하고 오류·저장 중·권한 없음 공통 상태를 보완한다.
2. 0-A 디자인을 사용자와 검토·확정한다. 이 단계에서는 DB를 변경하지 않는다.
3. 디자인 확정 뒤 1단계에서 P0 데이터 모델과 migration 파일을 작성한다.
4. Dev DB 초기화·migration 적용은 파일 검토 후 사용자 승인이 필요하다.

### 0단계 일부 완료 — 2026-08-26
- 구현: 루트 Next.js 16·TypeScript·Tailwind 뼈대, Clerk Development 로그인·회원가입 주소, 보호된 업무 화면 그룹, `AppShell`, `PageHeader`, 빈 화면, 기능별 기본 폴더와 빈 업무 주소.
- DB: 변경 없음. Supabase Dev·Production, migration, seed 모두 변경하지 않음.
- 코드 확인: `npx -y clerk@latest doctor`, `npm run lint`, `npm run typecheck`, `npm run build` 통과.
- 브라우저 확인: 개발 서버 시작만 확인. 실제 로그인·로그아웃과 모바일 메뉴 확인은 남음.
- 남은 작업: 0단계 공통 상태 UI 보완 뒤 0-A 목업 데이터 기반 전체 디자인 검증으로 진행.

### 0-A 디자인 검증 일부 완료 — 2026-08-26
- 구현: 가공 상담·매물·건물·계약 데이터, 상담 목록·상세, 상담 조건 매물 검색, 제안 화면 복귀, 업무 인박스, 건물·호실 3단 탐색기, 계약 목록, 광고비·문구 목업.
- DB: 변경 없음. 모든 화면은 코드 안의 가공 목업 데이터만 사용한다.
- 코드 확인: `npm run lint`, `npm run typecheck`, `npm run build` 통과.
- 브라우저 확인: 미실행. 로그인, 모바일, 화면 이동과 오류 상태 확인이 남아 있다.
- 남은 작업: 공통 오류·저장 중·권한 없음 상태와 브라우저 검토 후 사용자 디자인 확정.
