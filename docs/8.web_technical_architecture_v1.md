# 기술 아키텍처

## 확정 기술

Next.js App Router, React, TypeScript, Tailwind CSS, shadcn/ui, React Hook Form, Zod, TanStack Table, date-fns, Clerk, Supabase Postgres, Vercel을 사용한다.

별도 Python API, Express, ORM, Redux, Redis, tRPC, GraphQL, 마이크로서비스는 추가하지 않는다.

## 코드 구조

`app`은 라우트 조립, `features`는 업무 UI·서버 처리, `components/shared`는 재사용 UI, `components/ui`는 기초 부품, `lib`은 권한·DB·날짜·금액 공통 함수로 나눈다.

각 기능은 예를 들어 `features/listings/components`, `features/listings/server`, `features/listings/schemas`처럼 나눈다. 페이지 파일이나 한 컴포넌트에 조회·저장·검증·표·다이얼로그를 함께 넣지 않는다. 기능별 분리는 유지하되, 한 줄짜리 표시 요소까지 불필요하게 파일로 나누지는 않는다.

확정 폴더 전체 구조와 새 기능 추가 위치는 `REBUILD_MASTER_SPEC.md`의 **확정 폴더 트리**를 단일 기준으로 사용한다. 이 구조를 바꿔야 할 필요가 생기면, 먼저 기준서와 TODO를 수정하고 사용자에게 이유를 알린다.

## 데이터 접근

- 브라우저 요청만으로 조직을 결정하지 않는다.
- 서버에서 Clerk 사용자와 멤버십을 확인한다.
- DB 변경은 `supabase/migrations`의 순서 파일로 남긴다.
- migration 파일 작성은 DB 적용 승인이 아니다.

## 품질 기준

기능마다 Zod 검증, 오류 표시, 중복 저장 방지, 관련 테스트를 포함한다. lint·typecheck·build 결과와 브라우저 확인 결과를 따로 기록한다.
