# 화면 명세·디자인 적용 기준

## 1. 화면 설계의 중심

이 서비스는 화려한 대시보드나 고객 공개용 매물 사이트가 아니다. **상담을 시작으로 고객의 입주와 계약을 완료하는 목록 중심 부동산 업무 CRM**이다.

- 상담 관리는 대표 업무 화면이다. 리드부터 상담 이력·다음 행동·계약 결과까지 한 고객의 흐름을 관리한다.
- 매물 관리는 상담 중 제안할 상품의 재고를 등록·검색·수정하는 화면이다.
- 계약 관리는 상담의 결과를 실제 계약과 일정·금액·단계 이력으로 확정하는 화면이다.
- 오늘 예정 업무는 별도 대시보드가 아니라, 오늘 처리해야 할 일을 짧게 모아 주는 보조 화면이다.
- 건물·호실 화면은 재고를 건물 → 호실 → 현재/과거 매물 순서로 찾고 정리하는 탐색기다.

### 업무 흐름

```text
리드 유입 → 상담 등록·조건 파악 → 후속 연락·방문 이력
        → 적합 매물 제안·확인 → 계약 생성·진행 → 계약 완료·후속 관리
```

최초 문의 매물과 실제 계약 매물은 다를 수 있다. 두 기록은 계약에서 각각 연결해, 상담의 출처와 실제 성과를 모두 남긴다.

## 2. 메뉴와 주소

사이드바 메뉴는 아래 순서로 둔다. `상담 관리`를 가장 먼저 두며, 오늘 예정 업무는 작고 단순한 보조 메뉴로 둔다.

| 메뉴 | 주소 | 역할 | 단계 |
| --- | --- | --- | --- |
| 상담 관리 | `/consultations` | 리드·고객·상담 단계·이력·다음 행동을 관리하는 대표 화면 | P1 |
| 오늘 예정 업무 | `/dashboard` | 오늘·지연된 후속 연락, 방문, 계약, 매물 확인만 모아 보는 보조 화면 | P1 |
| 매물 관리 | `/listings` | 상담에 제시할 매물 재고의 검색·비교·현재 조건 관리 | P0 |
| 신규 매물 | `/listings/new` | 건물·호실과 현재 매물을 등록 | P0 |
| 매물 상세/수정 | `/listings/[id]`, `/listings/[id]/edit` | 재고 상세와 연결 상담·계약 요약 확인 | P0 |
| 건물·호실 탐색기 | `/buildings` | 건물 → 호실 → 현재/과거 매물을 탐색·관리 | P0 |
| 계약 관리 | `/contracts` | 실제 계약 매물·출처 상담·일정·금액·단계 이력 관리 | P1 |
| 광고 관리 | `/advertisements?view=cost`, `/advertisements?view=copy` | 상단 전환 배지로 분리한 월별 플랫폼 광고비와 매물 유형별 문구 템플릿 | P1 |

로그인 직후 기본 주소는 `/consultations`로 한다. 상담 데이터가 아직 없거나 권한·초기 설정이 끝나지 않은 경우에는 이해하기 쉬운 빈 화면과 `첫 상담 등록` 행동을 보여 준다.

## 3. 화면별 명세

### 3-1. 상담 관리 — 대표 업무 화면

**목적:** 새 문의를 리드로 기록하고, 고객이 계약 또는 종료 상태가 될 때까지 상담의 모든 다음 행동을 놓치지 않는다.

**기본 형태:** 통계 카드가 많은 대시보드가 아니라, 검색·필터가 있는 상담 목록을 넓게 보여 주는 업무 화면이다.

| 영역 | 표시 내용 | 사용자 행동 |
| --- | --- | --- |
| 상단 | `상담 관리` 제목, 검색, `신규 상담 등록` 버튼 | 고객·연락처·상담번호 검색, 새 리드 등록 |
| 단계 필터 | 구분, 상담 상태, 진행 단계, 종료 사유, 상담일 기간, 다음 연락 필요, 집중 대응 | 현재 처리 단계와 확인 우선순위로 목록 좁히기 |
| 상담 목록 | 고객 식별명·연락처, 유입 경로, 희망 조건 요약, 최초 문의 매물, 마지막 이력, 다음 연락일, 상담 상태·진행 단계 | 행을 열어 상담 상세로 이동 |
| 지연 표시 | 다음 연락일이 지났거나 오늘인 상담만 눈에 띄는 텍스트 배지 | 상담 상세에서 후속 기록 추가 |
| 빠른 행동 | 행에서 `이력 추가`, `다음 연락 변경`, `계약 생성` | 긴 화면 이동 없이 자주 하는 행동 처리 |

- 고객 연락처는 같은 조직의 로그인 직원이 후속 연락에 쓰도록 기본 표시한다. 상세 상담 메모·내부 메모·매물의 제한 연락처·출입 정보는 목록에 표시하지 않는다.
- 기본 정렬은 상담일 최신순으로 두고, 다음 연락 24시간 이내는 `최우선`, 72시간 이내는 `집중 대응` 배지와 필터로 따로 확인한다.
- 휴대폰에서는 같은 정보를 상담 카드로 보여 주되, 다음 연락일과 단계는 항상 보이게 한다.

### 3-2. 상담 상세 — 고객별 업무 타임라인

**목적:** 한 리드 또는 고객의 조건, 매물 제안, 통화·문자·방문 이력, 다음 행동, 계약 결과를 한곳에서 이어 본다.

| 영역 | 표시 내용 | 사용자 행동 |
| --- | --- | --- |
| 상단 요약 | 고객 식별명·연락처, 상담 상태, 진행 단계, 다음 연락일 | 상태·단계·다음 연락일 수정 |
| 희망 조건 | 복수 지역, 복수 방 구조·기타 입력, 예산, 입주 희망일, 필수 조건 | 조건 수정 |
| 연결 매물 | 최초 문의 매물과 현재 상태 요약 | 매물 상세 열기 |
| 상담 타임라인 | 최초 문의부터 전화·문자·방문·메모·상태 변경을 시간순 누적 | 새 이력 추가, 잘못된 이력 제한 수정 |
| 계약 결과 | 연결된 계약의 실제 계약 매물, 진행 상태, 주요 일정 | `계약 생성` 또는 계약 상세 열기 |

- 후속 이력은 최초 상담 내용을 덮어쓰지 않고 항상 누적한다.
- 계약 생성 시 현재 상담을 `출처 상담`으로 자동 선택한다. 실제 계약 매물은 사용자가 별도로 선택한다.
- 상담 종료는 종료 사유를 남기고 다음 연락일을 해제한다. 계약 진행·완료는 이 화면에서 바꾸지 않으며, 계약관리의 연결 계약 상태가 기준이다.

### 3-3. 오늘 예정 업무 — 작고 단순한 오늘의 할 일

**목적:** 업무의 원본을 새로 만들지 않고, 이미 저장된 상담·계약·매물에서 오늘 처리할 항목만 빠르게 확인한다.

**기본 형태:** 대형 지표·차트 중심의 첫 화면이 아니다. 짧은 목록과 원래 기록으로 가는 링크만 제공한다.

1. 지연된 상담 다음 연락
2. 오늘 연락할 상담
3. 오늘/임박한 방문·계약·잔금·입주·만기 일정
5. 퇴실 예정일·퇴실 확인·다음 임차인 안내 전 확인

- 각 항목은 원래 상담·계약·매물 상세로 이동한다.
- 완료 체크는 인박스 항목의 확인 여부만 기록하며, 상담·계약·매물 원본의 상태나 날짜를 임의로 바꾸지 않는다.
- 기본 그룹은 `지연됨`, `오늘`, `이번 주`이며, 모든 항목에 `상담`, `매물`, `퇴실`, `계약`, `확인` 업무 종류 텍스트 배지를 함께 표시한다.
- 상담 관리 화면에는 인박스 패널을 두지 않는다. 대신 목록 상단에 `지연`, `오늘 연락`처럼 상담에만 해당하는 작은 필터와 건수를 둔다. 전체 오늘 예정 업무는 독립 화면으로 확인한다.

### 3-4. 매물 관리 — 목록 중심 재고 관리

**목적:** 상담 중 필요한 매물을 빠르게 찾고, 현재 조건이 맞는지 비교·수정한다.

**기본 형태:** 넓은 표 중심 화면이다. 기본 목록에는 상태, 건물명, 주소, 호실, 구조, 가격, 입주 조건, 매물번호를 표시한다.

- 건물명·주소·호실·매물번호 검색과 상태·거래 유형·가격·입주 조건 필터를 제공한다. 기본 목록은 `관리 중 매물`로, 계약 완료 확정 매물은 현재 재고에서 제외한다. 과거 계약 매물은 건물·호실 관리의 이력에서 읽기 전용으로 확인한다.
- 연락처·출입 정보·내부 메모는 기본 목록에 표시하지 않는다.
- 목록에서 상태를 빠르게 수정하거나, 종료일·사유·확인을 거쳐 관리를 종료할 수 있다.
- 매물 상세에서는 연결 상담과 계약을 요약으로 보여 주되, 상담 자체를 매물 화면에서 관리하지 않는다.

### 3-5. 건물·호실 탐색기 — 재고 구조 관리

**목적:** 건물 단위로 호실과 현재/과거 매물을 정확히 찾아 수정한다.

**기본 형태:** `건물 목록 → 선택 건물의 호실 목록 → 선택 호실의 매물 상세` 3단 탐색기다.

- 건물 목록에는 건물명·주소·호실 수를, 호실 목록에는 호실·층·구조·현재 상태를 표시한다.
- 선택 호실에서는 현재 매물과 종료된 과거 매물 이력을 구분해 보여 준다. 과거 이력은 당시의 가격·상태·입주 조건을 읽기 전용 상세 화면에서 확인하며, 수정 화면으로 이동하지 않는다.
- 건물·호실의 공통 정보는 이 화면에서 수정한다.
- 상담 관리가 필요할 때는 선택 매물에 연결된 상담 요약만 보여 주고, 자세한 상담 처리는 상담 상세로 이동한다.

### 3-6. 계약 관리 — 상담 성과와 실제 계약 관리

**목적:** 실제 계약 매물, 출처 상담, 일정·금액·중개 방식·단계 이력을 안전하게 관리한다.

**기본 형태:** 계약 상태와 가까운 일정을 빠르게 비교하는 목록, 한 건의 경과를 남기는 상세 화면이다.

- 목록에는 계약 상태, 실제 계약 매물, 출처 상담 식별명, 계약일·입주일·만료일, 잔금 일정만 표시한다.
- 계약 상세에는 실제 계약 매물과 출처 상담을 명확히 구분한다.
- 가계약·정식계약·잔금 예정·완료·해지 같은 단계는 시간순으로 누적한다.
- 계약 상태 또는 계약 단계 이력을 저장하면 실제 계약 매물을 자동 반영한다. 계약 진행·잔금 예정은 매물을 계약 진행으로, 계약 완료는 계약 완료 과거 이력으로 바꾼다. 해지·만료는 아직 계약 진행인 매물만 공실로 되돌리고, 종료된 과거 이력은 다시 열지 않는다. 계약 일정 날짜는 오늘 예정 업무를 만들 뿐 상태를 자동 변경하지 않는다.

## 4. 공통 상태와 정보 보호

모든 실제 업무 화면에 로딩, 데이터 없음, 오류, 저장 중, 권한 없음, 삭제·상태 변경 확인 창을 제공한다.

- 상태는 색상만이 아니라 텍스트 배지로 표시한다.
- 페이지마다 강조하는 주 행동 버튼은 하나만 둔다.
- PC는 표·다단 탐색을 우선하고, 휴대폰은 상담 확인·검색·상세·간단 수정 흐름을 우선한다.
- 매물의 제한 연락처, 출입 비밀번호, 계좌·내부 메모는 매물 목록·오늘 예정 업무·광고 화면에 표시하지 않는다. 고객 연락처는 후속 연락 업무를 위해 현재 같은 조직 직원의 상담 목록·상세에서만 표시하며, 후속 권한 기능에서 admin이 직원별 열람을 제한한다.
- Excel·CSV 다운로드는 MVP 화면에 두지 않는다.
- `app/**/page.tsx`는 화면 조립만 하며, 상담 목록·타임라인·인박스·매물 표·건물 탐색기·계약 목록은 각 `features`의 별도 컴포넌트로 만든다.

## 5. 화면 완성 기준

각 화면은 이 문서의 업무 역할, 모바일 핵심 확인, 오류·빈 상태, 공통 부품 재사용을 만족해야 한다. 정적 디자인 시안은 참고 자료일 뿐이며, 이 문서의 상담 중심 업무 흐름과 보안 규칙을 우선한다.
