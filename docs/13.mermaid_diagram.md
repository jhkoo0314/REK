# 웹프로젝트 업무 흐름 다이어그램

> 기준일: 2026-08-31
> 이 다이어그램은 현재 웹서비스에서 직원이 매물·상담·계약 업무를 처리하는 큰 흐름을 보여 줍니다.

```mermaid
flowchart TD
    A[로그인] --> B{사무실 조직 선택 여부}
    B -- 선택 안 함 --> C[조직 선택 안내]
    C --> B
    B -- 선택함 --> D[상담관리]

    D --> E[새 상담 등록]
    E --> F[최초 문의 매물 연결 선택]
    F --> G[상담 내용과 다음 연락일 저장]
    G --> H[상담 상세]
    D --> H
    H --> I[후속 이력 추가<br/>전화·문자·방문]
    I --> J[오늘 할 일에 표시]
    J --> H

    D --> K[매물관리]
    K --> L[대표 필터·상세 필터로 매물 검색]
    L --> M[매물 상세 확인]
    M --> N[일반 조건 수정 또는 빠른 수정]
    N --> K
    K --> O[새 매물 등록]
    O --> P[건물 → 호실 → 현재 매물 저장]
    P --> K
    K --> Q[관리 종료 처리]
    Q --> R[종료일·종료 사유 기록 후 과거 이력으로 이동]

    K --> S[건물·호실 관리]
    S --> T{현재 매물이 있는 호실인가?}
    T -- 예 --> M
    T -- 아니오 --> U[최근 과거 조건을 불러온 새 공실 매물 등록]
    U --> P

    H --> V[계약 등록]
    K --> V
    V --> W[매물번호·건물명·주소·호수로 계약 매물 검색]
    W --> X[선택한 매물의 계약 입력창 열기]
    X --> Y[계약 정보·단계 기록 저장]
    Y --> Z{계약 상태}
    Z -- 진행 --> AA[매물: 계약 진행]
    Z -- 완료 --> AB[매물: 계약 완료<br/>상담: 계약 성사로 종료]
    Z -- 해지 또는 만료 --> AC[계약 이력 보존]
    AC --> AD{기존 매물이 계약 완료였고<br/>현재 매물이 없는가?}
    AD -- 예 --> AE[같은 호실에 새 공실 매물 생성]
    AD -- 아니오 --> AF[기존 매물 이력 유지]
    AE --> K
    AF --> K

    D --> AG[오늘 할 일]
    AG --> J
    AG --> AH[완료 처리 또는 빠른 처리]
    AH --> H

    K --> AI[광고관리]
    AI --> AJ[매물 조건을 넣어 광고 문구 생성]
    AJ --> AK[문구 수정·복사]
    AI --> AL[월별 광고비 기록]

    AM[구성원 권한] --> AN[직원별 민감정보 열람 권한 설정]
```

## 상태 변경 원칙

```mermaid
flowchart LR
    A[매물 일반 수정] --> B[같은 현재 매물의 조건만 수정]
    C[빠른 수정] --> D[공실·보류만 변경 가능]
    E[계약관리] --> F[계약 진행·완료·해지·만료 기록]
    F --> G[매물 상태에 반영]
    H[관리 종료] --> I[종료일·사유 기록]
    I --> J[과거 이력으로 보관]
```

## 참고

- 계약 완료 뒤 해지·만료 처리와 새 공실 자동 생성은 migration 파일에 작성되어 있으며, Dev DB 적용 상태는 `PROJECT_STRUCTURE_INDEX.md`와 `CURRENT_IMPLEMENTATION_STATUS.md`에서 확인합니다.
- 사진 유무와 재확인일은 현재 웹 업무와 DB에서 제거하는 방향으로 정리되어 있습니다.
