# 사용자 접근·권한 정책

## 역할

| 역할 | 권한 |
| --- | --- |
| admin | 사무실 업무 전체 처리, 멤버 관리·비활성화, 광고 문구 템플릿 관리 |
| staff | 매물·상담·계약·오늘 할 일·광고비 처리, 광고 문구 템플릿 생성·수정·사용 중지·삭제 |
| inactive | 로그인해도 업무 데이터 접근 불가 |

## 공통 정책

- 로그인은 Clerk로 처리한다.
- 서버는 Clerk 사용자와 활성 `organization_members`를 확인한다.
- 업무 데이터에는 모두 `organization_id`를 둔다. 브라우저가 보낸 조직 ID는 신뢰하지 않는다.
- 기본 시작 화면은 중요업무알림(`/dashboard`)이다.
- 다른 조직·비활성·미로그인 사용자는 업무 데이터를 읽거나 바꿀 수 없다.
- 광고 문구 템플릿은 같은 조직의 active admin·staff가 모두 생성·수정·사용 중지·삭제할 수 있다.

## 민감 정보

- 연락처는 `building_contacts`, 출입 비밀번호와 출입 메모는 `unit_access_details`에 분리해 저장한다.
- 현재 구현에서는 admin과 active staff가 **자기 조직의 건물·호실 상세 화면에서 사용자가 직접 열람할 때만** 제한 정보를 볼 수 있다. inactive·멤버 없음·다른 조직 사용자는 볼 수 없다.
- admin은 `/members`에서 staff별로 건물·호실 연락처, 세대 비밀번호·출입 정보, 상담 고객 연락처의 열람 권한을 따로 허용·해제한다. admin은 항상 전체를 열람하고, staff는 권한 행이 없거나 허용되지 않은 항목을 볼 수 없다. 내부 메모는 현재 별도 민감정보 필드가 아니므로 실제 도입 시 별도 권한 항목으로 추가한다.
- 기본 매물 목록·빠른 검색·오늘 예정 업무·광고 문구·목업 데이터에는 포함하지 않는다. Excel·CSV 다운로드는 MVP에서 제공하지 않는다.
- 연락처·출입 비밀번호를 매물 표의 열, URL, 알림 문구, 브라우저 로그에 넣지 않는다. Production 전환 시 별도 RLS 정책과 열람 기록 필요 여부를 확인한다.
- `consultations`의 고객 연락처는 후속 연락을 위한 업무 정보이지만, admin과 허용된 staff에게만 상담 기본 목록·상세, 계약의 출처 상담 선택, 오늘 업무에서 표시한다. 매물·광고에는 표시하지 않는다.

## 확인 기준

- [ ] admin과 staff가 자기 조직 업무를 처리한다.
- [ ] inactive와 멤버 없음 계정이 차단된다.
- [ ] 다른 조직 ID를 주소에 넣어도 데이터를 볼 수 없다.
- [ ] admin·허용된 staff가 자기 조직의 상세에서만 제한 정보를 열람할 수 있고, 기본 목록에는 나오지 않는다.
- [ ] admin이 staff별 민감정보 열람을 허용·해제할 수 있고, 해제 뒤 목록·상세·계약 선택·오늘 업무·비밀번호 요청에서 값이 보이지 않는다.
- [ ] 상담 기본 목록의 고객 연락처는 admin과 허용된 staff에게만 보이고, 다른 업무 목록·다른 조직에는 보이지 않는다.
- [ ] MVP 화면에 Excel·CSV 다운로드 기능이 없다.
