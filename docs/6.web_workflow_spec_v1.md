# 부동산 매물관리 웹서비스 — 업무 워크플로우 명세서 v1.0

## 1. 문서 목적

이 문서는 매물관리 웹서비스에서 사용자가 실제로 하는 일을 **입력 → 처리 → 결과** 기준으로 정의한다. 화면 명세, API 구현, 테스트의 공통 기준으로 사용한다.

대상은 원룸·투룸 중심 임대 중개 업무이며, 한 사무실 안에서 `admin`과 `staff`가 함께 사용하는 1차 운영 버전이다.

### 1.1 핵심 원칙

- 매물 정보는 `건물 → 호실 → 매물` 순서로 관리한다.
- 가격·상태·입주 가능일의 일반 수정은 기존 매물을 수정한다. 같은 호실에 새 매물을 자동 생성하지 않는다.
- 매물·상담·계약·광고 현황은 서로 연결되지만, 한 화면에서 모두 입력하도록 복잡하게 만들지 않는다.
- 목록에서는 판단에 필요한 정보만 빠르게 보고, 상세에서만 민감하거나 긴 정보를 본다.
- 사용자가 저장한 결과는 즉시 다시 확인할 수 있어야 한다.

## 2. 1차 출시 범위

| 구분 | 이번 버전에 포함 | 이후 확장 |
| --- | --- | --- |
| 로그인 | Clerk 로그인, admin/staff 구분 | 다중 사무실 전환, 세분화된 역할 |
| 매물 | 등록·조회·검색·필터·수정·상태 변경 | 대량 수정, 변경 이력 화면 |
| 건물/호실 | 검색 후 기존 선택 또는 새로 등록 | 건물주 전용 관리 화면 |
| 상담 | 상담 등록, 연결 매물, 다음 연락일, 완료 처리 | 문자 발송 연동, 상담 분석 |
| 계약 | 계약 등록·수정, 금액·일정·입금 상태 관리 | 전자서명, 정산 자동화 |
| 광고 | 채널별 등록 상태, 광고 문구 생성·복사 | 채널 API 등록, 광고 성과 분석 |
| 오늘 할 일 | 입주·퇴실·계약·상담 후속 일정 확인, 완료 체크 | 알림·반복 업무 자동화 |
| 사진 | 기본 화면에서는 후순위 | 비공개 업로드·정렬·대표사진 |

### 2.1 이번 버전에서 하지 않는 일

- 당근·네이버·직방 등에 직접 자동 등록하지 않는다.
- 고객 또는 임대인에게 자동으로 문자를 발송하지 않는다.
- 매물 수정 때 계약·상담·광고 기록을 자동으로 삭제하거나 새로 만들지 않는다.
- 확정 전 매물 정보를 다른 사무실 사용자에게 공유하지 않는다.

## 3. 공통 사용 흐름

### 3.1 로그인과 업무 시작

| 단계 | 사용자 행동 | 시스템 처리 | 결과 |
| --- | --- | --- | --- |
| 1 | 서비스 접속 | 로그인 여부 확인 | 미로그인 시 Clerk 로그인 화면 표시 |
| 2 | 로그인 | 활성 멤버십과 역할 확인 | 접근 가능하면 대시보드 이동 |
| 3 | 업무 시작 | 해당 조직 데이터만 불러오기 | 오늘 할 일과 최근 매물 현황 표시 |

멤버십이 없거나 비활성 상태인 사용자는 업무 데이터 화면으로 들어갈 수 없다. `staff`는 일반 업무를 처리할 수 있고, `admin`은 여기에 사용자·사무실 설정 관리 권한이 추가된다.

### 3.2 공통 저장 규칙

1. 필수값이 비어 있거나 금액·날짜 형식이 맞지 않으면 저장하지 않고 해당 입력칸을 알려 준다.
2. 저장 시 로그인 사용자의 조직 ID를 서버가 부여한다. 화면에서 조직 ID를 입력하거나 바꿀 수 없다.
3. 저장 성공 후에는 “저장됨” 안내와 함께 변경된 상세 또는 목록을 바로 보여 준다.
4. 삭제는 한 번 더 확인받는다. 계약 또는 상담이 연결된 매물은 삭제 대신 상태 변경을 우선 제안한다.
5. 목록에서 수정해도 상위·하위 기록의 연결은 유지한다.

## 4. 오늘 할 일 확인 워크플로우

### 목적

업무 시작 시 놓치기 쉬운 입주·퇴실·계약·상담 후속 연락을 한 곳에서 확인하고 처리한다.

| 구분 | 내용 |
| --- | --- |
| 입력 | 오늘 날짜, 매물 입주 가능일·퇴실 예정일, 계약 일정·입금 상태, 상담 다음 연락일, 완료 체크 |
| 처리 | 시스템이 날짜와 상태를 비교해 할 일을 계산하고, 사용자가 완료 여부를 기록 |
| 출력 | 오늘 처리할 일 목록, 지연된 업무, 빠른 이동 버튼 |

### 업무 규칙

| 할 일 유형 | 표시 조건 | 완료 시 처리 |
| --- | --- | --- |
| 입주 확인 | 오늘이 입주일이거나 입주 확인이 미완료 | `task_completions`에 완료 기록 |
| 퇴실·공실 확인 | 퇴실 예정일 도래 또는 공실 확인 필요 | 완료 기록 후 매물 상태 확인 화면으로 이동 |
| 계약 일정 | 계약일·잔금일이 오늘 또는 임박 | 완료 기록, 계약 상세로 이동 가능 |
| 상담 후속 연락 | 다음 연락일이 오늘 이전 또는 오늘 | 완료 기록 또는 다음 연락일 재설정 |

완료 체크는 원본 매물·상담·계약 데이터를 삭제하지 않는다. 같은 업무를 다시 확인해야 할 경우에는 날짜나 상태를 변경하여 새 업무가 계산되게 한다.

## 5. 신규 매물 등록 워크플로우

### 목적

새로 받은 매물을 중복 없이 빠르게 등록하고, 이후 상담·계약·광고에 바로 연결한다.

### 흐름

| 단계 | 사용자 행동 | 시스템 처리 | 다음 결과 |
| --- | --- | --- | --- |
| 1 | 주소·건물명으로 건물 검색 | 같은 조직의 기존 건물 후보 표시 | 기존 건물 선택 또는 새 건물 등록 |
| 2 | 건물 선택 후 호실 검색 | 선택한 건물의 호실 후보 표시 | 기존 호실 선택 또는 새 호실 등록 |
| 3 | 매물 조건 입력 | 임대 조건, 입주 가능일, 상태, 옵션 등 검증 | 매물 등록 준비 |
| 4 | 저장 | 선택한 건물·호실과 연결해 현재 매물 생성 | 매물 상세 화면 이동 |
| 5 | 필요 시 광고 문구 생성 또는 광고 상태 기록 | 저장된 매물 정보를 기본값으로 사용 | 외부 채널 등록 작업으로 이어짐 |

### 등록 전 확인 규칙

| 상황 | 시스템 동작 | 사용자 선택 |
| --- | --- | --- |
| 같은 건물·호실에 현재 매물이 있음 | 중복 경고와 기존 매물 핵심 정보 표시 | 기존 매물 수정으로 이동 또는 명확한 사유 확인 후 계속 |
| 건물은 있으나 호실이 없음 | 새 호실 등록 폼 표시 | 호실만 추가 후 매물 입력 계속 |
| 호실은 있으나 이전 매물이 종료됨 | 기존 호실을 선택 가능 | 새 현재 매물 등록 |
| 필수 임대 조건이 누락됨 | 저장 차단 | 누락 항목 입력 |

### 신규 매물의 최소 입력값

- 건물명 또는 주소
- 호실
- 매물 유형(원룸·투룸·쓰리룸·상가 등)
- 거래 유형(월세·전세 등)
- 보증금, 월세, 관리비
- 매물 상태(공실·입주 가능일 조율 중 등)
- 입주 가능일 또는 확인 필요 상태

건물주 연락처, 출입 관련 정보, 세부 옵션 등은 가능한 한 함께 기록하되, 현장 상황상 나중에 입력할 수 있다.

## 6. 기존 매물 조회·수정 워크플로우

### 목적

수백 개의 매물 중 필요한 호실을 빨리 찾고, 실제 변동 사항을 현재 매물에 정확히 반영한다.

### 목록에서 하는 일

| 행동 | 입력 | 처리 | 출력 |
| --- | --- | --- | --- |
| 검색 | 건물명, 주소, 호실, 매물번호 | 부분 일치 검색 | 관련 매물 목록 |
| 필터 | 매물 유형, 가격대, 상태, 입주 가능일, 광고 상태 | 조건을 함께 적용 | 처리 대상만 남긴 목록 |
| 빠른 수정 | 상태, 보증금·월세, 입주 가능일 | 값 검증 후 현재 매물 수정 | 변경값 즉시 반영 |
| 상세 열기 | 특정 행 선택 | 관련 상담·계약·광고 현황 요약 조회 | 매물 상세 화면 |

### 상세에서 하는 일

| 업무 | 처리 기준 |
| --- | --- |
| 가격·관리비 변경 | 기존 `listings` 행을 수정한다. 새 매물을 자동 생성하지 않는다. |
| 공실·계약됨·보류 상태 변경 | 상태, 변경 시각, 필요 시 사유를 저장한다. |
| 입주 가능일 변경 | 오늘 할 일 계산에 바로 반영한다. |
| 옵션·특징·메모 보완 | 동일 매물의 세부 정보만 보완한다. |
| 상담·계약·광고 열기 | 이미 연결된 기록을 보여 주고, 새 기록도 같은 매물에 연결해 생성한다. |

### 매물 상태 기준

| 상태 | 의미 | 다음 행동 |
| --- | --- | --- |
| 공실 | 바로 안내 또는 계약 가능한 상태 | 광고·상담 연결 |
| 입주 가능 예정 | 퇴실·정비·일정 확인이 필요한 상태 | 날짜 확인, 오늘 할 일 표시 |
| 협의 중 | 조건·입주일 등을 확인 중 | 최신 확인일 기록 |
| 계약 진행 | 특정 고객과 계약 절차 진행 중 | 계약 정보 연결 |
| 계약 완료 | 신규 안내와 광고를 중단해야 하는 상태 | 광고 종료 확인 |
| 보류 | 임대인 확인 또는 내부 사유로 일시 중지 | 보류 사유와 재확인일 기록 |

## 7. 상담 관리 워크플로우

### 목적

문의 고객의 조건과 다음 연락 약속을 남겨, 방문·계약까지의 후속 관리를 놓치지 않는다.

### 흐름

| 단계 | 사용자 행동 | 시스템 처리 | 결과 |
| --- | --- | --- | --- |
| 1 | 상담 추가 | 고객명/연락처/문의 채널/조건/문의일 입력 | 상담 기본 기록 생성 |
| 2 | 매물 연결(선택) | 현재 매물 검색 후 연결 | 어떤 매물을 안내했는지 확인 가능 |
| 3 | 통화·문자·방문 내용 기록 | 상담 메모와 결과 입력 | 상담 이력 누적 |
| 4 | 다음 연락일 지정 | 날짜와 할 일 유형 저장 | 오늘 할 일에 자동 표시 |
| 5 | 종결 또는 계속 관리 | 결과 상태 변경 | 상담 현황에 반영 |

### 상담 상태 기준

| 상태 | 의미 | 필수 또는 권장 기록 |
| --- | --- | --- |
| 신규 문의 | 첫 문의가 들어온 상태 | 문의 채널, 희망 조건 |
| 조건 확인 | 예산·입주일·선호 위치 확인 중 | 조건과 다음 연락일 |
| 매물 제안 | 맞는 매물을 안내한 상태 | 제안 매물 또는 메모 |
| 방문 예정 | 현장 안내 일정이 잡힌 상태 | 방문 일시 |
| 계약 진행 | 계약으로 연결된 상태 | 연결 계약 |
| 보류 | 추후 연락 또는 조건 재확인 필요 | 보류 사유, 다음 연락일 |
| 종료 | 계약·타사 계약·미응답 등으로 종료 | 종료 사유 |

고객이 여러 매물을 본 경우에도 상담은 한 건으로 유지하고, 제안·방문 이력에 매물 연결을 추가한다. 같은 고객의 완전히 다른 문의가 새로 들어오면 새 상담을 만든다.

## 8. 계약 관리 워크플로우

### 목적

계약 일정과 금액·입금 확인을 매물 및 상담 기록과 연결해 관리한다.

### 흐름

| 단계 | 사용자 행동 | 시스템 처리 | 결과 |
| --- | --- | --- | --- |
| 1 | 계약 등록 | 매물 선택, 필요 시 상담 선택 | 선택한 기록과 계약 연결 |
| 2 | 조건 입력 | 보증금·월세·관리비·계약일·입주일 등 검증 | 계약 초안 저장 |
| 3 | 진행 상태 업데이트 | 가계약·계약 예정·계약 완료 등 반영 | 오늘 할 일과 매물 상태에 반영 |
| 4 | 입금·잔금 확인 | 확인일과 상태 기록 | 미확인 업무 표시 |
| 5 | 계약 완료 처리 | 계약 완료일 입력 | 연결 매물의 광고 종료 확인 필요 표시 |

### 계약 상태와 매물 연동 규칙

| 계약 상태 | 연결 매물의 기본 처리 | 주의점 |
| --- | --- | --- |
| 계약 검토/가계약 | 매물을 자동으로 종료하지 않음 | 광고 상태와 실제 안내 가능 여부를 사용자가 확인 |
| 계약 진행 | 매물 상태를 `계약 진행`으로 변경할 수 있게 제안 | 자동 변경 전 확인 필요 |
| 계약 완료 | 매물 상태를 `계약 완료`로 변경할 수 있게 제안 | 기존 광고의 종료 여부를 반드시 확인 |
| 계약 취소 | 매물 상태를 이전 상태 또는 `공실`로 되돌릴 수 있게 제안 | 실제 공실·입주 가능일 확인 후 반영 |

계약과 매물 상태의 변경은 사용자의 확인 후 저장한다. 자동 연동으로 현재 매물 상태를 잘못 바꾸지 않도록 한다.

## 9. 광고 관리 및 광고 문구 워크플로우

### 목적

매물별로 어느 채널에 광고가 등록되어 있는지 확인하고, 반복적인 광고 문구 작성 시간을 줄인다.

### 9.1 광고 현황 관리

| 단계 | 사용자 행동 | 시스템 처리 | 결과 |
| --- | --- | --- | --- |
| 1 | 매물 상세에서 광고 현황 열기 | 연결된 채널 기록을 조회 | 당근·네이버·직방 등 상태 확인 |
| 2 | 채널 추가 또는 상태 변경 | 채널, 등록일, 상태, 메모 저장 | 광고 현황 반영 |
| 3 | 매물 상태 변경 후 광고 확인 | 계약 완료·보류 매물의 활성 광고를 표시 | 종료·수정해야 할 광고 확인 |

광고 상태는 `등록 예정`, `게시 중`, `수정 필요`, `중지`, `종료`로 관리한다. 외부 채널 등록 자체는 사용자가 채널 사이트에서 직접 한다.

### 9.2 광고 문구 생성

| 구분 | 내용 |
| --- | --- |
| 입력 | 선택한 매물의 기본 조건, 템플릿, 강조 포인트, 선택한 광고 채널 |
| 처리 | 누락된 핵심 조건을 확인하고 채널에 맞는 문구 조합 생성 |
| 출력 | 제목 후보와 본문 문구. 사용자가 복사해 외부 채널에 붙여넣기 |
| 저장 원칙 | 생성된 문구만으로 매물 DB를 수정하지 않는다. 필요하면 사용자가 최종 문구를 광고 메모에 저장한다. |

생성 전에 가격·상태·입주 가능일이 최신인지 표시한다. 계약 완료 또는 보류 매물은 새 광고 문구 생성을 막고, 상태 확인을 먼저 안내한다.

## 10. 연결 관계와 데이터 처리 기준

| 시작 기록 | 연결 가능한 기록 | 연결 방식 | 삭제/변경 시 기준 |
| --- | --- | --- | --- |
| 건물 | 호실 | 건물 1개에 여러 호실 | 호실이 있으면 건물 삭제 대신 비활성화 검토 |
| 호실 | 매물 | 호실 1개에 과거 매물 여러 개 가능 | 현재 매물은 일반 수정으로 유지 |
| 매물 | 상담 | 매물 1개에 여러 상담 가능 | 매물 수정과 상담 이력은 독립 유지 |
| 매물 | 계약 | 매물 1개에 계약 기록 연결 | 계약이 있으면 매물 삭제 대신 상태 변경 |
| 매물 | 광고 현황 | 매물 1개에 여러 채널 기록 | 계약 완료 시 활성 광고 종료 확인 |
| 상담 | 후속 연락/계약 | 상담 1개에 여러 후속 기록, 계약 연결 가능 | 상담 종료해도 기록 보존 |

## 11. 권한과 안전장치

| 기능 | staff | admin |
| --- | --- | --- |
| 매물·상담·계약·광고 조회 및 관리 | 가능 | 가능 |
| 오늘 할 일 완료 처리 | 가능 | 가능 |
| 본인 조직 데이터 조회 | 가능 | 가능 |
| 사용자 초대·비활성화 | 불가 | 가능 |
| 사무실 설정 변경 | 불가 | 가능 |

모든 워크플로우는 로그인한 사용자의 조직 데이터 안에서만 실행한다. 다른 조직의 ID를 URL·폼·개발자 도구로 넣어도 조회·저장·수정되지 않아야 한다.

## 12. 사용자에게 보여 줄 결과 기준

| 상황 | 보여 줄 내용 |
| --- | --- |
| 저장 성공 | 무엇이 저장되었는지, 마지막 저장 시각, 다음 할 일 또는 이동 버튼 |
| 저장 실패 | 실패 이유와 수정해야 할 입력 항목. 기술 오류 문구는 그대로 노출하지 않음 |
| 검색 결과 없음 | 현재 조건에 맞는 매물이 없다는 안내와 필터 초기화 또는 신규 등록 제안 |
| 중복 가능성 | 기존 건물·호실·현재 매물의 핵심 정보와 선택지 |
| 접근 불가 | 권한이 없거나 멤버십이 비활성이라는 간단한 안내 |
| 계약 완료 매물 | 광고 종료 확인, 새 상담 안내 중지 등 다음 처리 항목 |

## 13. 1차 출시 완료 기준

- [ ] 로그인 후 자기 조직의 오늘 할 일과 매물 현황을 볼 수 있다.
- [ ] 기존 건물·호실을 검색해 새 매물을 등록할 수 있다.
- [ ] 같은 호실의 일반 가격·상태 변경이 기존 현재 매물에 반영된다.
- [ ] 매물 목록에서 검색·필터·빠른 수정이 가능하다.
- [ ] 상담에 매물, 후속 연락일, 결과를 연결할 수 있다.
- [ ] 계약에 매물과 일정을 연결하고 입금·완료 상태를 관리할 수 있다.
- [ ] 매물별 광고 채널 상태를 기록하고 광고 문구를 생성·복사할 수 있다.
- [ ] 계약 완료 매물의 광고 종료 확인 업무가 표시된다.
- [ ] admin과 staff의 사용자 관리 권한이 구분된다.
- [ ] 다른 조직의 데이터는 어떤 흐름에서도 보거나 바꿀 수 없다.
