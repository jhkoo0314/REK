# Supabase 데이터 모델

> 새 migration은 이 문서를 기준으로 작성하며, 파일 작성과 Dev 적용을 구분한다.

> P0 열 이름·필수 여부·상태값·검증 규칙의 확정본은 `P0_DATA_FIELD_SPEC.md`를 따른다.

## 공통 규칙

- 기본키는 UUID, 업무 데이터에는 `organization_id`, `created_at`, `updated_at`을 둔다.
- 금액은 만원 단위 정수, 업무 날짜는 `date`, 기록 시각은 `timestamptz`를 쓴다.
- 일반 수정은 현재 매물 행을 `update`한다. 자동으로 새 회차를 만들지 않는다.
- P1 계약 관리에서 계약 상태 또는 계약 단계 이력을 저장하면 `contracts.listing_id`로 연결된 현재 매물을 자동 전환한다. `계약 진행`·`잔금 예정`은 `contract_in_progress`, `계약 완료`는 `contract_complete`·`is_current = false` 과거 이력으로 바꾼다. `해지`·`만료`는 아직 계약 진행인 매물만 `vacant`로 되돌리며, 종료된 과거 이력은 다시 열지 않는다.

| 단계 | 테이블 | 핵심 내용 |
| --- | --- | --- |
| P0 | organizations, organization_members | 조직, Clerk 사용자 ID, admin/staff, 활성 여부 |
| P0 | buildings | 주소·공통 정보 |
| P0 | units | 호수 정규화, 구조·방향·옵션 |
| P0 | building_contacts | 건물별 제한 연락처와 대표 연락처 표시 |
| P0 | unit_access_details | 호실별 제한 출입 비밀번호·출입 메모 |
| P0 | listings | 매물 표시번호(`M-000001`), 매물 종류, 현재 매물 조건, 가격·입주·사진 보유 여부·재확인·현장 상태·보유처 |
| P1 | consultations, consultation_followups | 일반/매물 상담, 고객 연락처·희망 조건·다음 연락, 전화·문자·방문 후속 이력 |
| P1 | contracts, contract_activities | 실제 계약 매물, 출처 상담, 일정·금액·중개 방식·단계 이력 |
| P1 | task_completions | 계산된 업무의 완료 체크만 저장 |

| P2 예정 | organization_member_sensitive_permissions | 멤버별 연락처·출입 정보·내부 메모 열람 허용 여부 |

## 반드시 막을 것

- 같은 조직에서 같은 건물·정규화 호실 중복
- 호실당 현재 매물 두 건
- 다른 조직의 건물·호실·매물·상담·계약 연결
- 음수 금액과 앞뒤가 맞지 않는 날짜
- 같은 기준연월·광고 채널 광고비 중복

## 데이터 관계

```text
조직 → 건물 → 호실 → 현재/과거 매물
                         ├─ 상담 → 후속 이력
                         └─ 계약 → 단계 이력
건물 → 제한 연락처
호실 → 제한 출입 정보
계산된 업무 → 완료 체크
조직 → 월별 광고비
조직 → 매물 유형별 광고 문구 템플릿
조직 멤버 → 민감정보 열람 권한(후속)
```

사진 파일·매물별 광고 채널 테이블·Excel 내보내기용 테이블은 이번 재빌드 범위에 넣지 않는다.

## P1 광고 관리 저장 규칙

- `monthly_advertising_costs`는 기준연월과 플랫폼 조합을 조직 안에서 하나만 둔다. 기본 플랫폼은 당근·네이버·직방·기타이며, 기타는 플랫폼명을 직접 적는다. 비용은 만원 단위의 0 이상 정수다.
- 월별 광고비는 각 플랫폼의 한 달 총액만 저장한다. 매물·상담·계약과 연결하지 않고, 현 단계에서 성과를 자동 계산하지 않는다.
- `advertising_copy_templates`는 조직별로 관리한다. 매물 유형(원룸·투룸, 아파트, 오피스텔, 상가·사무실), 템플릿명, 제목 양식, 본문 양식, 사용 여부, 생성·수정 사용자와 시각을 둔다.
- 템플릿은 확인한 매물 값만 표시하는 자리표시자만 쓴다. 연락처, 출입 비밀번호, 출입 메모, 내부 메모용 자리표시자는 허용하지 않는다.
- 템플릿 결과를 매물·광고 기록에 따로 저장하지 않는다.

## 후속 민감정보 권한 규칙

- `organization_member_sensitive_permissions`는 admin이 같은 조직 멤버에게 민감정보별 열람 허용 여부를 설정하기 위한 후속 P2 테이블이다. 지금은 migration을 작성하거나 Dev DB에 적용하지 않는다.
- 처음 구분할 항목은 건물·호실 연락처, 출입 비밀번호·출입 메모, 상담 고객 연락처, 내부 메모다. 새 민감 항목은 하나의 넓은 권한에 묶지 않고 별도 항목으로 검토한다.
- 이 테이블을 실제 도입할 때 서버 조회와 Production RLS가 같은 권한을 확인해야 한다. 화면에서만 숨기고 서버가 값을 보내는 방식은 허용하지 않는다.

## P1 상담 저장 규칙

- `consultations`에는 일반/매물 구분, 최초 문의 매물(일반 상담은 처음에 비워둘 수 있음), 고객 식별명·연락처, 상담일·유입 경로·상담 방식·상담 메모를 저장한다.
- 희망 지역·방 구조는 복수 선택과 기타 직접 입력을 허용하고, 예산·희망 입주일·필수 조건 메모를 함께 저장한다.
- 상담 상태는 `진행 중`, `보류`, `종료`, `확인 필요`로, 진행 단계는 `신규 문의`, `조건 확인`, `방문 예정`, `방문 완료`, `검토 중`, `종료`로 분리한다. `계약 진행`·`계약 완료`는 상담에서 선택하거나 변경할 수 없다.
- `consultation_followups`에는 일자, 방식(전화·문자·방문·기타), 진행 단계, 방문 결과, 종료 사유, 다음 연락일, 메모를 누적한다. 추가·수정·삭제 후 상담의 최신 상담일·마지막 후속 이력·다음 연락·단계 요약을 다시 계산한다.
- 상담을 종료하면 다음 연락일을 비운다. 일반 상담은 후에 최초 문의 매물을 연결할 수 있다.

## P1 계약 저장 규칙

- `contracts`는 같은 조직의 현재 매물을 실제 계약 매물로 필수 연결하고, 출처 상담은 선택으로 연결한다. 출처 상담의 최초 문의 매물과 실제 계약 매물이 달라도 저장을 막지 않는다.
- 거래 방식은 매물과 같은 월세·전세·매매·확인 필요로 기록한다. 계약 구분은 신규 계약·재계약으로 별도 기록하며, 중개 방식은 단독·공동·기타로 구분한다. 금액은 만원 단위 정수이며 전체 계약금·가계약금·잔금과 관련 예정일을 각각 기록한다.
- 계약 진행일, 정식 계약일, 입주일, 만료일은 앞뒤 날짜가 맞아야 하며 가계약금은 전체 계약금보다 클 수 없다.
- `contract_activities`에는 가계약·정식 계약·잔금 완료·계약 완료·해지·만료를 시간순으로 누적한다. 단계 이력은 기존 계약 내용을 덮어쓰지 않는다.
- 계약 상태 또는 단계 이력 저장은 실제 계약 매물에만 반영한다. 계약 진행·잔금 완료는 `contract_in_progress`, 계약 완료는 `contract_complete`와 과거 이력 전환, 해지·만료는 아직 계약 진행인 현재 매물만 `vacant`로 되돌린다. 계약 완료면 출처 상담을 종료하고 다음 연락일을 해제한다.

## P1 오늘 할 일 계산 규칙

- 기준일은 사용자가 바꿔 확인할 수 있으며, 기준일 변경은 원본 기록·완료 기록을 바꾸지 않는다.
- 매물 재확인 예정일과 사진·현장 상태의 상시 확인 필요 업무는 웹 범위에서 제외한다. 마지막 재확인일(`last_confirmed_date`)은 매물 정보 확인용으로만 유지한다.
- 계약 일정은 정식 계약일, 계약금 추가 수령 예정일, 잔금 예정일, 임대차 종료일을 각각 계산한다. 일정 날짜는 업무만 만들며 상태를 바꾸지 않는다.
- 상담 업무에는 고객 연락처를 표시하고, 오늘 할 일 화면에서 상담 상태·다음 연락일을 바로 수정할 수 있다. 계약 업무에서는 계약 상태를 바로 변경할 수 있으며, 모두 각 원본의 조직·상태 전환 규칙을 통과해야 한다.

## 매물 종류 확장 규칙

- `listings.property_type`은 원룸, 투룸, 아파트, 오피스텔, 상가, 사무실을 구분한다. P0 화면에서는 원룸·투룸만 실제 선택·검증한다.
- 방 구조는 주거형 매물에만 적용하며 상가·사무실은 빈값을 허용한다.
- 건물은 복합 용도일 수 있으므로, 매물 종류의 기준은 건물 전체가 아니라 매물에 둔다.
- 아파트 단지·동·공급면적 또는 상가 권리금·부가세·용도처럼 전용 항목은 실제 도입 시 별도 migration으로 추가한다.
