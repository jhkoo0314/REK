# 부동산 매물관리 웹서비스 — 화면 명세·와이어프레임 v1.0

## 1. 문서 목적

이 문서는 `web_workflow_spec_v1.md`에서 정의한 업무 흐름을 실제 웹 화면으로 옮긴 기준이다. 개발자는 화면의 범위와 동작을, 운영자는 어떤 화면에서 어떤 일을 처리하는지를 같은 기준으로 확인한다.

1차 화면의 목표는 화려한 대시보드가 아니라 다음 세 가지다.

1. 오늘 놓치면 안 되는 일을 먼저 본다.
2. 수백 개 매물에서 필요한 호실을 빠르게 찾고 수정한다.
3. 매물에서 상담·계약·광고 현황으로 자연스럽게 이어진다.

---

## 2. 화면 구조 원칙

| 원칙 | 적용 방식 |
| --- | --- |
| 업무 우선 | 숫자보다 오늘 처리할 일, 매물 상태, 다음 행동을 먼저 보여 준다. |
| 목록 우선 | 매물은 표 형태로 빠르게 비교하고, 긴 내용은 상세 화면에서 본다. |
| 한 번에 한 가지 | 신규 등록·수정·상담·계약을 같은 긴 폼에 섞지 않는다. |
| 안전한 수정 | 빠른 수정은 자주 바뀌는 값만 허용하고, 삭제·계약 상태 변경은 한 번 더 확인한다. |
| 민감 정보 최소 노출 | 연락처·계좌·출입 정보는 목록에서 숨기고 상세에서 필요한 경우에만 표시한다. |
| 상태가 보이는 UI | 공실·계약 진행·계약 완료·보류를 색상만이 아니라 텍스트 배지로 명확히 표시한다. |

## 3. 전체 정보 구조와 메뉴

### 3.1 좌측 메뉴(데스크톱 기준)

| 구역 | 메뉴 | 목적 | 기본 진입 여부 |
| --- | --- | --- | --- |
| 업무 시작 | 대시보드 | 오늘 할 일과 현재 현황 확인 | 로그인 후 기본 화면 |
| 핵심 관리 | 매물 관리 | 매물 검색·등록·수정·상세 확인 | 핵심 화면 |
| 고객 관리 | 상담 관리 | 신규 문의와 다음 연락 관리 | 필요 시 진입 |
| 거래 관리 | 계약 관리 | 계약 일정·금액·입금 상태 관리 | 필요 시 진입 |
| 외부 노출 | 광고 현황 | 채널별 게시 상태와 수정 필요 매물 확인 | 필요 시 진입 |
| 관리 | 사용자 관리 | 초대·권한·비활성화 | admin만 표시 |
| 관리 | 사무실 설정 | 조직 기본 설정 | admin만 표시, 1차는 최소 기능 |

매물 상세 안에서도 상담·계약·광고 현황을 볼 수 있다. 상단 메뉴의 상담·계약·광고 현황은 여러 매물을 가로질러 “처리 대상 전체”를 찾을 때 사용한다.

### 3.2 권장 URL 구조

| 화면 | URL | 비고 |
| --- | --- | --- |
| 로그인 | `/sign-in` | Clerk 제공 화면 사용 |
| 대시보드 | `/dashboard` | 로그인 후 기본 이동 |
| 매물 목록 | `/listings` | 검색·필터 상태는 URL에 반영 가능 |
| 신규 매물 | `/listings/new` | 건물→호실→매물 등록 |
| 매물 상세 | `/listings/[listingId]` | 탭 기반 상세 |
| 매물 수정 | `/listings/[listingId]/edit` | 상세에서 진입 |
| 상담 목록 | `/consultations` | 전체 상담 관리 |
| 상담 상세 | `/consultations/[consultationId]` | 후속 연락 이력 포함 |
| 계약 목록 | `/contracts` | 전체 계약 관리 |
| 계약 상세 | `/contracts/[contractId]` | 연결 매물·상담 표시 |
| 광고 현황 | `/advertisements` | 전체 채널 상태 보기 |
| 사용자 관리 | `/settings/members` | admin 전용 |

## 4. 공통 레이아웃과 디자인 기준

### 4.1 데스크톱 레이아웃

| 영역 | 구성 | 역할 |
| --- | --- | --- |
| 좌측 사이드바 | 로고/사무실명, 메뉴, 하단 사용자 메뉴 | 현재 위치와 주요 업무 이동 |
| 상단 헤더 | 페이지 제목, 짧은 설명, 전역 검색(후순위), 사용자 메뉴 | 현재 업무 맥락 표시 |
| 본문 상단 | 핵심 수치 또는 처리 대상 요약, 주요 버튼 | 판단과 빠른 행동 |
| 본문 | 표·카드·상세 패널 | 실제 업무 처리 |
| 우측 보조 영역 | 필요할 때만 Drawer 또는 상세 패널 | 목록 맥락을 유지한 채 확인 |

- 데스크톱 기준 본문 최대 폭은 약 1,600px로 두고, 표가 좁아지지 않게 한다.
- 매물 목록은 가로 스크롤을 숨기지 않는다. 화면 폭이 부족하면 덜 중요한 열을 숨기고, 필요 시 `더보기`로 확장한다.
- 기본 배경은 차분한 밝은 회색, 업무 카드와 표는 흰색으로 분리한다.

### 4.2 모바일 대응 범위

1차는 사무실 PC 사용을 우선하되, 휴대폰에서 오늘 할 일·매물 검색·상세 확인·간단한 상태 변경은 가능해야 한다.

| 항목 | 데스크톱 | 모바일 |
| --- | --- | --- |
| 메뉴 | 고정 사이드바 | 상단 메뉴 버튼 또는 하단 주요 메뉴 |
| 매물 목록 | 다열 표 | 핵심 정보 카드형 목록 |
| 필터 | 한 줄 필터바 | 필터 Drawer |
| 상세 | 탭과 2열 정보 | 세로 섹션, 탭은 가로 스크롤 |
| 신규 등록 | 단계별 넓은 폼 | 동일 단계, 한 열 입력 |
| 빠른 수정 | 표 안 입력 또는 팝오버 | Bottom sheet 또는 별도 수정 화면 |

사진 대량 업로드, 복잡한 계약 입력, 사용자 관리는 1차 모바일 우선 범위에서 제외한다.

### 4.3 시각 체계

| 항목 | 기준 |
| --- | --- |
| 글자 | 제목은 굵고 짧게, 본문은 읽기 쉬운 크기, 보조 정보는 낮은 대비로 구분 |
| 여백 | 화면 외곽 24~32px, 카드 내부 16~24px, 폼 항목 간 16px 이상 |
| 색상 | 기본은 중립색. 상태·경고·삭제에만 제한적으로 색 사용 |
| 버튼 | 페이지당 주 행동은 1개만 강조. 나머지는 보조 버튼 또는 메뉴로 처리 |
| 아이콘 | 메뉴·상태 보조용으로만 사용하고, 텍스트 의미를 대체하지 않음 |
| 피드백 | 저장·복사·완료·오류에는 즉시 토스트와 화면 내 상태 변화를 함께 표시 |

### 4.4 상태 배지 기준

| 배지 | 색상 방향 | 사용 위치 |
| --- | --- | --- |
| 공실 | 파랑 계열 | 매물 목록·상세 |
| 입주 가능 예정 / 협의 중 | 노랑·주황 계열 | 매물 목록·오늘 할 일 |
| 계약 진행 | 보라 계열 | 매물·계약 목록 |
| 계약 완료 | 회색·초록 계열 | 매물·계약·광고 현황 |
| 보류 | 회색 계열 | 매물 목록 |
| 지연 업무 | 빨강 계열 | 대시보드·상담·계약 목록 |

색을 인식하지 못해도 상태를 알 수 있도록 모든 배지는 상태명을 함께 표시한다.

## 5. 화면별 명세

### SCR-01. 로그인 및 접근 불가

| 항목 | 내용 |
| --- | --- |
| 목적 | 초대된 사용자만 서비스에 들어오게 한다. |
| 주요 구성 | 사무실/서비스명, Clerk 로그인·로그아웃, 접근 불가 안내 |
| 주 행동 | 로그인 |
| 성공 결과 | 활성 멤버는 `/dashboard`로 이동 |
| 예외 결과 | 멤버십 없음 또는 비활성 시 “관리자에게 계정 확인을 요청해 주세요” 안내 |

로그인 화면에는 매물·고객·계약 정보가 보이지 않는다. 직접 가입 버튼은 1차에서 숨기고 초대 기반으로 운영한다.

---

### SCR-02. 대시보드

| 항목 | 내용 |
| --- | --- |
| 목적 | 오늘의 업무 우선순위를 정하고 바로 처리 화면으로 이동한다. |
| 주 사용자 | admin, staff |
| 주 행동 | 오늘 할 일 열기, 매물 등록, 매물 검색 |

#### 화면 구성

| 영역 | 구성 요소 | 표시 내용 | 행동 |
| --- | --- | --- | --- |
| 상단 | 인사와 날짜 | “8월 14일 금요일 · 오늘 처리할 일” | 없음 |
| 상단 우측 | `+ 신규 매물 등록` | 가장 자주 쓰는 행동 | 신규 매물 화면 이동 |
| 우선 카드 | 오늘 처리할 일 | 입주, 퇴실/공실 확인, 상담 연락, 계약 일정 개수 | 해당 필터 목록 이동 |
| 우선 목록 | 지연된 업무 | 기한이 지난 항목 최대 5건 | 상세 또는 완료 처리 |
| 현황 카드 | 현재 공실, 입주 가능 예정, 계약 진행, 광고 수정 필요 | 상태별 건수 | 매물/광고 목록 필터 이동 |
| 최근 활동 | 최근 수정 매물·상담·계약 | 제목, 변경자, 변경 시각 | 해당 상세 이동 |

#### 표시 우선순위

1. 지연된 업무
2. 오늘 처리할 일
3. 공실·계약 진행·광고 수정 필요 현황
4. 최근 활동

대시보드에는 복잡한 매출 차트나 장식용 그래프를 넣지 않는다. 숫자를 누르면 항상 처리 가능한 목록으로 이동해야 한다.

### SCR-03. 매물 목록

| 항목 | 내용 |
| --- | --- |
| 목적 | 매물을 빠르게 찾고 비교·수정한다. |
| 주 사용자 | admin, staff |
| 주 행동 | 검색, 필터, 빠른 수정, 상세 열기, 신규 매물 등록 |

#### 상단 영역

| 요소 | 내용 | 동작 |
| --- | --- | --- |
| 페이지 제목 | `매물 관리`와 현재 결과 수 | 기본 맥락 표시 |
| 주 버튼 | `+ 신규 매물 등록` | SCR-04 이동 |
| 통합 검색 | 건물명·주소·호실·매물번호 검색 | 입력 후 즉시 또는 Enter로 적용 |
| 빠른 필터 | 상태, 유형, 거래 유형, 입주 가능일 | 많이 쓰는 조건만 노출 |
| 전체 필터 | 가격대, 관리비, 광고 상태, 옵션 등 | Drawer로 열어 복잡도 분리 |
| 필터 초기화 | 적용된 조건 표시와 초기화 | 목록 원상 복구 |

#### 기본 표 열

| 우선 | 열 | 표시 방식 | 비고 |
| --- | --- | --- | --- |
| 필수 | 상태 | 텍스트 배지 | 공실/계약 진행 등 |
| 필수 | 건물·호실 | 건물명, 호실, 주소 보조표시 | 행의 대표 정보 |
| 필수 | 유형 | 원룸/투룸/쓰리룸/상가 | 짧은 배지 또는 텍스트 |
| 필수 | 임대 조건 | 보증금 / 월세, 관리비 보조표시 | 통화 단위를 일정하게 표기 |
| 필수 | 입주 가능 | 날짜 또는 “즉시/확인 필요” | 오늘 할 일과 연결 |
| 권장 | 광고 | 게시 중 채널 수 또는 수정 필요 배지 | 상세에서 전체 확인 |
| 권장 | 최근 수정 | 날짜·수정자 | 오래된 정보 판단용 |
| 선택 | 빠른 수정 | 상태·가격·입주 가능일 | 자주 변하는 값만 |

#### 행 동작

| 행동 | 결과 |
| --- | --- |
| 행의 건물·호실 선택 | 매물 상세(SCR-05)로 이동 |
| 상태 배지 선택 | 상태 변경 팝오버 열기 |
| 가격 영역 선택 | 빠른 수정 팝오버 열기 |
| 더보기 메뉴 | 수정, 복제 등록(후순위), 삭제/비활성화 등 노출 |
| 체크박스 | 1차에서는 기본 제외. 대량 작업이 확정되면 추가 |

`빠른 수정`은 보증금·월세·관리비·상태·입주 가능일로 한정한다. 건물·호실·민감 정보·계약 연결은 상세 화면에서만 수정한다.

#### 빈 화면과 오류 화면

| 상황 | 화면 처리 |
| --- | --- |
| 등록 매물 없음 | “첫 매물을 등록해 보세요”와 신규 등록 버튼 |
| 검색 결과 없음 | 검색어·필터를 보여 주고 `필터 초기화` 제공 |
| 데이터 불러오기 실패 | 새로고침 버튼과 간단한 오류 안내 |
| 접근 불가 | 목록을 비우고 권한 안내 |

### SCR-04. 신규 매물 등록

| 항목 | 내용 |
| --- | --- |
| 목적 | 건물·호실 중복을 줄이며 현재 매물을 등록한다. |
| 주 행동 | 건물 선택/등록 → 호실 선택/등록 → 매물 조건 저장 |
| 형식 | 한 페이지 안의 3단계 섹션. 현재 단계만 펼쳐서 입력 부담을 줄임 |

#### 단계별 구성

| 단계 | 입력 구성 | 완료 조건 | 화면 동작 |
| --- | --- | --- | --- |
| 1. 건물 찾기 | 건물명/주소 검색, 기존 후보, `새 건물 등록` | 기존 건물 선택 또는 새 건물 저장 | 다음 단계 자동 활성화 |
| 2. 호실 선택 | 선택 건물의 호실 목록·검색, `새 호실 추가` | 호실 선택 또는 새 호실 저장 | 현재 매물 중복 여부 확인 |
| 3. 매물 조건 | 유형, 거래 유형, 보증금, 월세, 관리비, 상태, 입주 가능일, 옵션·메모 | 필수값 검증 통과 | 저장 버튼 활성화 |

#### 입력 화면 규칙

| 항목 | 기준 |
| --- | --- |
| 건물 검색 결과 | 주소와 기존 호실 수를 함께 보여 혼동을 줄인다. |
| 새 건물 입력 | 건물명, 주소는 필수. 건물주·계좌 등 민감 정보는 접어서 선택 입력으로 둔다. |
| 호실 선택 | 기존 호실에 현재 매물이 있으면 상태·가격·최근 수정일을 함께 표시한다. |
| 중복 경고 | 같은 호실의 현재 매물이 있으면 저장 버튼 대신 `기존 매물 열기`를 우선 제안한다. |
| 금액 | 숫자만 입력하고 화면에는 한국식 금액 단위로 보조 표기한다. |
| 임시 저장 | 1차에서는 제외. 새로고침/이탈 시 입력 내용 소실 경고를 표시한다. |

#### 하단 행동

| 버튼 | 표시 조건 | 결과 |
| --- | --- | --- |
| 취소 | 항상 | 목록으로 돌아가기 전 입력 소실 확인 |
| 이전 | 2·3단계 | 바로 앞 단계 수정 |
| 매물 등록 | 필수값 충족 | 저장 후 새 매물 상세로 이동 |

### SCR-05. 매물 상세

| 항목 | 내용 |
| --- | --- |
| 목적 | 한 호실의 최신 조건과 연결된 상담·계약·광고 업무를 한 맥락에서 처리한다. |
| 주 행동 | 매물 수정, 상태 변경, 상담 추가, 계약 추가, 광고 확인/문구 생성 |

#### 헤더

| 요소 | 내용 |
| --- | --- |
| 경로 | 매물 관리 / 건물명 / 호실 |
| 대표 제목 | `건물명 000호 · 유형` |
| 핵심 정보 | 상태, 보증금/월세, 입주 가능일, 최근 수정 시각 |
| 주요 버튼 | `수정`, `상태 변경`, `+ 상담`, `+ 계약` |
| 보조 메뉴 | 광고 문구 생성, 비활성화/삭제(조건부) |

#### 탭 구성

| 탭 | 핵심 내용 | 주 행동 |
| --- | --- | --- |
| 기본 정보 | 가격·관리비·상태·입주 가능일·옵션·메모 | 수정 |
| 상담 | 연결 상담의 상태·다음 연락일·최근 이력 | 상담 추가, 상담 상세 열기 |
| 계약 | 계약 상태·주요 일정·입금 확인 | 계약 추가, 계약 상세 열기 |
| 광고 | 채널별 상태, 수정 필요 여부, 광고 메모 | 채널 상태 변경, 문구 생성 |
| 활동 | 생성·수정·상태 변경 기록 | 1차는 읽기 전용, 변경 이력 고도화는 후순위 |

#### 기본 정보의 카드 구성

| 카드 | 표시 정보 | 노출 원칙 |
| --- | --- | --- |
| 임대 조건 | 보증금, 월세, 관리비, 거래 유형 | 항상 표시 |
| 입주·상태 | 현재 상태, 입주 가능일, 퇴실/확인 메모 | 항상 표시 |
| 공간 정보 | 유형, 층, 방향, 옵션, 특징 | 일반 정보 |
| 건물·호실 | 주소, 건물명, 호실, 주차 등 | 일반 정보 |
| 관리 정보 | 담당 메모, 최근 수정 | 기본은 접기 가능 |
| 민감 정보 | 연락처·계좌·출입 관련 정보 | 기본 접힘, 상세 권한/필요 시만 표시 |

계약 완료 또는 보류 상태라면 상단에 주의 배너를 보여 주고, 새 광고 문구 생성보다 광고 종료·상태 확인 행동을 우선 배치한다.

### SCR-06. 매물 수정 및 상태 변경

| 항목 | 내용 |
| --- | --- |
| 목적 | 기존 매물을 새로 만들지 않고 최신 정보로 정확히 바꾼다. |
| 진입 | 매물 상세의 `수정`, 목록의 빠른 수정 |
| 형식 | 전체 수정은 전용 페이지, 단순 상태·가격 변경은 팝오버 또는 Drawer |

#### 전체 수정 폼

| 구역 | 수정 항목 | 주의 |
| --- | --- | --- |
| 임대 조건 | 보증금, 월세, 관리비, 거래 유형 | 저장 전 현재 값과 변경 값 확인 |
| 상태·일정 | 상태, 입주 가능일, 확인 필요일, 보류 사유 | 오늘 할 일 계산에 반영 |
| 공간 정보 | 옵션, 특징, 면적 참고, 방향 등 | 광고 문구 기본값에 사용 |
| 건물·호실 | 필요한 경우에만 수정 | 이미 연결된 기록이 있으면 경고 후 진행 |
| 메모 | 내부 메모 | 목록에는 노출하지 않음 |

#### 상태 변경 팝오버

| 입력 | 조건 |
| --- | --- |
| 새 상태 | 필수 |
| 변경 사유 | 보류·계약 취소 시 권장 또는 필수 |
| 입주 가능일 | 공실/입주 가능 예정으로 변경 시 권장 |
| 광고 처리 확인 | 계약 완료·보류 시 활성 광고가 있으면 표시 |

저장 후 매물 상세의 핵심 정보·대시보드·광고 현황이 새 상태로 갱신되어야 한다.

### SCR-07. 상담 목록과 상담 상세

| 항목 | 상담 목록 | 상담 상세 |
| --- | --- | --- |
| 목적 | 후속 연락 대상을 찾는다. | 고객 조건과 이력을 관리한다. |
| 상단 필터 | 상태, 문의 채널, 다음 연락일, 담당자(후순위) | 해당 없음 |
| 핵심 정보 | 고객 식별명, 상태, 희망 조건 요약, 다음 연락일, 연결 매물 | 고객 조건, 문의 채널, 제안 매물, 이력 타임라인 |
| 주 행동 | `+ 상담 등록`, 행 선택 | 이력 추가, 다음 연락일 변경, 상태 변경, 계약 연결 |

#### 상담 목록 열

| 열 | 표시 내용 |
| --- | --- |
| 상태 | 신규 문의·방문 예정·보류·종료 등 |
| 고객 | 이름 또는 내부 식별명. 연락처는 기본 마스킹 |
| 문의 조건 | 희망 위치·예산·입주일의 짧은 요약 |
| 연결 매물 | 대표 1건 또는 `외 n건` |
| 다음 연락 | 날짜, 지연 여부 |
| 최근 활동 | 마지막 통화·문자·방문 기록 시각 |

#### 상담 상세의 이력 입력

| 입력 | 예시 |
| --- | --- |
| 이력 유형 | 통화, 문자, 방문, 매물 제안, 기타 |
| 내용 | 고객 반응, 조건 변경, 다음 행동 |
| 연결 매물 | 이번 이력에서 안내한 매물(복수 가능) |
| 다음 연락일 | 필요 시 지정 |
| 결과 상태 | 계속 관리, 방문 예정, 계약 진행, 보류, 종료 |

상담 메모는 자동으로 외부에 전송되지 않는다. 문자 내용이 필요할 때는 복사 가능한 문구를 별도 기능으로 제공할 수 있으나, 1차에서는 후순위다.

### SCR-08. 계약 목록과 계약 상세

| 항목 | 계약 목록 | 계약 상세 |
| --- | --- | --- |
| 목적 | 일정·입금 확인이 필요한 계약을 찾는다. | 계약 조건과 진행 상태를 관리한다. |

| 핵심 정보 | 연결 매물, 고객 식별명, 계약 상태, 계약일·입주일, 입금 상태 | 조건·일정·입금·연결 상담/매물 |

| 카드 | 내용 |
| --- | --- |
| 진행 상태 | 가계약/진행/완료/취소와 마지막 변경 시각 |
| 주요 일정 | 계약일, 잔금일, 입주일 |

| 연결 정보 | 매물 및 상담으로 이동하는 링크 |
| 내부 메모 | 안내·확인 관련 메모 |

계약 완료·취소 시에는 연결 매물 상태를 어떻게 처리할지 선택하는 확인 Dialog를 보여 준다. 기본 선택은 “매물 상태는 변경하지 않음”으로 두어 잘못된 자동 변경을 방지한다.

### SCR-09. 광고 현황과 문구 생성

| 항목 | 광고 현황 | 광고 문구 생성 |
| --- | --- | --- |
| 목적 | 채널별로 손봐야 할 매물을 찾는다. | 외부 등록용 문구를 빠르게 만든다. |
| 진입 | 좌측 메뉴 또는 매물 상세 광고 탭 | 매물 상세 또는 광고 현황 행 메뉴 |
| 핵심 정보 | 매물, 채널, 게시 상태, 등록/수정일, 메모 | 매물 조건, 템플릿, 강조 포인트, 생성 결과 |
| 주 행동 | 상태 변경, 매물 상세 열기 | 문구 생성, 복사 |

#### 광고 현황 목록 열

| 열 | 표시 내용 |
| --- | --- |
| 매물 | 건물·호실, 유형, 임대 조건 요약 |
| 매물 상태 | 공실·계약 진행·계약 완료 등 |
| 채널 | 당근·네이버·직방 등 |
| 광고 상태 | 등록 예정·게시 중·수정 필요·중지·종료 |
| 마지막 확인 | 날짜와 수정자 |
| 메모 | 짧은 내부 메모 일부 |

매물이 `계약 완료` 또는 `보류`인데 광고가 `게시 중`이면 가장 위에 경고로 표시한다.

#### 광고 문구 생성 Drawer

| 구역 | 구성 | 동작 |
| --- | --- | --- |
| 매물 확인 | 건물·호실, 가격, 상태, 입주 가능일 | 최신 정보인지 먼저 확인 |
| 템플릿 선택 | 원룸/투룸/쓰리룸 등 기본 템플릿 | 템플릿별 구성 변경 |
| 강조 포인트 | 체크 또는 짧은 문장 입력 | 문구에 반영 |
| 안내 문구 | 기본 안내사항 선택 | 채널별 길이 제한 고려 |
| 결과 | 제목 후보·본문 | 수정 가능, `복사` 버튼 제공 |

문구 생성 화면은 데이터를 저장하는 입력폼이 아니다. 사용자가 복사한 뒤 외부 채널에 직접 등록하고, 필요할 때만 광고 상태를 `게시 중`으로 바꾼다.

### SCR-10. 사용자 관리(admin)

| 항목 | 내용 |

| 주요 구성 | 사용자 목록, 역할, 상태, 초대 버튼, 비활성화 메뉴 |

## 6. 공통 컴포넌트·상호작용 명세

| 컴포넌트 | 사용 위치 | 동작 기준 |
| --- | --- | --- |
| 검색 입력창 | 매물·상담·계약 목록 | 입력 중 과도한 요청을 막고, 짧은 지연 후 검색 또는 Enter로 적용 |
| 필터 칩 | 목록 상단 | 적용 중인 조건을 한눈에 표시하고 개별 해제 가능 |
| 날짜 선택기 | 입주일·다음 연락일·계약일 | 직접 입력과 달력 선택 모두 지원 |
| 금액 입력 | 매물·계약 폼 | 숫자만 입력, 단위와 천 단위 구분 보조 표시 |
| 상태 배지 | 모든 목록·상세 | 클릭 가능한 경우 변경 가능함을 명확히 표시 |
| Drawer | 필터·광고 문구·간단 수정 | 원래 목록 맥락을 유지한 채 열기 |
| Dialog | 삭제·계약 완료·상태 영향 큰 변경 | 무엇이 바뀌는지 설명하고 확인받기 |
| Toast | 저장·복사·완료·오류 | 짧고 구체적인 결과 문구 표시 |
| Skeleton | 목록·상세 로딩 | 빈 화면 대신 구조를 먼저 보여 주기 |

### 6.1 버튼 문구 기준

| 상황 | 사용할 문구 | 피할 문구 |
| --- | --- | --- |
| 신규 매물 | `+ 신규 매물 등록` | `추가` |
| 저장 | `매물 등록`, `변경사항 저장` | `확인` |
| 상태 변경 | `상태 변경` | `수정` |
| 상담 이력 | `이력 추가` | `등록` |
| 계약 처리 | `계약 완료 처리`, `계약 취소 처리` | `처리` |
| 삭제 | `삭제하기` | 아이콘만 표시 |

버튼은 사용 후 일어나는 결과를 문구로 알려 준다.

## 7. 화면 간 이동 기준

| 시작 화면 | 행동 | 도착 화면 | 유지할 정보 |
| --- | --- | --- | --- |
| 대시보드 | 오늘 할 일 선택 | 매물/상담/계약 목록 | 해당 날짜·상태 필터 |
| 매물 목록 | 행 선택 | 매물 상세 | 목록의 검색·필터·스크롤 위치 |
| 매물 상세 | 상담 추가 | 상담 등록 | 매물 자동 연결 |
| 매물 상세 | 계약 추가 | 계약 등록 | 매물 자동 연결, 필요 시 상담 선택 |
| 상담 상세 | 계약 연결 | 계약 등록 | 상담·선택 매물 자동 연결 |
| 계약 상세 | 매물 선택 | 매물 상세 | 계약 상세로 돌아가기 가능 |
| 광고 현황 | 매물 선택 | 매물 상세 광고 탭 | 광고 상태 맥락 |

목록에서 상세로 갔다가 뒤로 돌아왔을 때, 사용자가 적용했던 검색·필터와 페이지 위치가 유지되어야 반복 작업이 줄어든다.

## 8. 접근성·오류 처리 기준

| 항목 | 기준 |
| --- | --- |
| 키보드 | 주요 버튼·입력·Dialog는 Tab과 Enter/Esc로 조작 가능 |
| 폼 오류 | 오류 이유를 해당 필드 가까이에 텍스트로 표시 |
| 색상 | 상태·오류를 색상만으로 전달하지 않음 |
| 로딩 | 버튼을 비활성화하고 진행 중임을 표시해 중복 저장 방지 |
| 저장 실패 | 입력 내용은 유지하고 다시 저장할 수 있게 함 |
| 권한 오류 | 기술적인 코드 대신 접근 불가 안내와 다음 행동 표시 |
| 삭제 | 대상 이름을 표시하고 연결 기록 영향 여부를 설명 |

## 10. 화면 완료 기준

- [ ] 로그인한 사용자는 대시보드에서 오늘 처리할 일을 우선순위대로 볼 수 있다.
- [ ] 매물 목록에서 건물명·주소·호실·매물번호 검색과 상태·가격대 필터를 사용할 수 있다.
- [ ] 매물 목록의 핵심 열만으로 공실 여부, 가격, 입주 가능일, 광고 상태를 판단할 수 있다.
- [ ] 신규 매물 등록 시 기존 건물·호실·현재 매물 중복 가능성을 확인할 수 있다.
- [ ] 매물 상세에서 기본 정보·상담·계약·광고를 연결해 볼 수 있다.
- [ ] 빠른 수정과 전체 수정의 범위가 구분되어 있다.
- [ ] 상담·계약 목록에서 다음 행동이 필요한 항목을 바로 찾을 수 있다.
- [ ] 광고 문구는 최신 매물 정보를 바탕으로 생성·복사할 수 있다.
- [ ] admin만 사용자 관리 메뉴와 행동을 볼 수 있다.
- [ ] PC와 휴대폰에서 핵심 정보를 읽고 기본 업무를 할 수 있다.
