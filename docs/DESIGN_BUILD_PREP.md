# 목록 중심 부동산 업무 CRM — 디자인 구현 가이드

> 기준일: 2026-08-26
>
> 우선 문서: `7.web_screen_spec_wireframe_v1.md`, `REBUILD_MASTER_SPEC.md`
> 목적: 상담을 중심으로 매물·계약·후속 업무가 연결되는 화면을 일관되게 구현한다.

## 1. 디자인 컨셉과 판단 기준

이 서비스는 고객에게 매물을 보여 주는 홍보 사이트도, 숫자·차트가 많은 대시보드도 아니다. 직원이 상담 한 건을 놓치지 않고 계약까지 처리하도록 돕는 **목록 중심 부동산 업무 CRM**이다.

```text
상담 관리: 고객이 누구이며 무엇을 원하는가
매물 관리: 조건에 맞는 재고가 무엇인가
계약 관리: 어떤 상담이 어떤 실제 계약으로 이어졌는가
오늘 예정 업무: 오늘 무엇을 먼저 처리해야 하는가
```

- 대표 화면은 `상담 관리`다. 로그인 후 이 화면을 연다.
- 매물은 상담에 제시할 재고다. 매물 검색·비교·조건 수정은 매물 관리 화면에서 한다.
- 상담 상세에서 `매물 찾기`를 누르면, 고객의 지역·예산·방 형태 등의 조건을 넣은 매물 목록으로 이동한다. 상담 화면 안에 복잡한 재고 표를 복제하지 않는다.
- 오늘 예정 업무는 작은 보조 화면이다. 오늘·지연 업무를 원래 상담·계약·매물 상세로 연결할 뿐, 별도 업무 원본을 만들지 않는다.
- 건물·호실은 재고를 정리하는 별도 탐색기다. 건물 → 호실 → 현재/과거 매물 순서로 본다.

최종 정적 시안은 `FINAL_CRM_UI_CONCEPT.html`이다. 이전 탐색용 시안은 참고 자료로만 남기며, 실제 구현의 업무 역할과 데이터 보호 기준은 이 문서와 화면 명세가 우선한다.

## 2. 정보 구조와 메뉴 순서

사이드바는 아래 순서로 고정한다. 매일 가장 많이 확인할 상담을 첫 메뉴로 둔다.

| 메뉴 | 주소 | 화면 성격 | 핵심 주 행동 |
| --- | --- | --- | --- |
| 상담 관리 | `/consultations` | 넓은 목록 + 상담 상세 타임라인 | 신규 상담 등록 |
| 오늘 예정 업무 | `/dashboard` | 짧은 오늘·지연 업무 목록 | 해당 기록 열기 |
| 매물 관리 | `/listings` | 검색·필터가 있는 재고 표 | 새 매물 등록 |
| 건물·호실 | `/buildings` | 3단 탐색기 | 건물·호실 정보 수정 |
| 계약 관리 | `/contracts` | 계약 목록 + 단계 이력 | 새 계약 작성 |
| 광고비·문구 | `/advertisements` | 월별 기록·직접입력 문구 | 광고비 입력 |

`/dashboard`는 첫 화면으로 사용하지 않는다. 상담 목록이 비어 있으면 빈 화면에 `첫 상담 등록` 하나를 가장 눈에 띄게 둔다.

## 3. 화면별 디자인 규칙

### 3-1. 상담 관리 — 가장 중요한 목록

상담 목록은 한 줄에서 고객의 다음 행동을 판단할 수 있어야 한다. 큰 성과 카드나 차트보다 검색, 단계 필터, 다음 연락일이 우선이다.

| 목록 열 | 표시 방식 | 주의점 |
| --- | --- | --- |
| 단계 | 텍스트가 있는 상태 배지 | 색상만으로 구분하지 않음 |
| 고객 식별명 | 굵은 기본 정보 | 전체 연락처를 기본 표시하지 않음 |
| 유입 경로 | 짧은 보조 텍스트 | 예: 전화, 방문, 소개 |
| 희망 조건 | 지역·예산·방 형태 요약 | 긴 요청은 상세에서 확인 |
| 연결 매물 | 건수 또는 짧은 요약 | 매물 상세로 이동 가능 |
| 마지막 상담 | 날짜와 행동 종류 | 전화·문자·방문 구분 |
| 다음 연락 | 날짜와 오늘/지연 배지 | 지연 항목을 가장 명확히 표시 |
| 담당자 | 짧은 이름 또는 이니셜 | 권한에 따라 표시 |

- 기본 정렬: `지연 → 오늘 연락 → 다음 연락일 빠른 순 → 최근 수정 순`.
- 자주 쓰는 단계 필터: 신규, 연락 예정, 상담 진행, 방문 예정, 계약 검토, 계약 완료, 종료.
- 행을 누르면 상담 상세를 열고, 행 안의 빠른 행동은 `이력 추가`, `다음 연락 변경`, `계약 생성`만 제공한다.
- 상담 관리 화면에는 우측 오늘 예정 업무 패널을 두지 않는다. 대신 목록 상단에 `지연`, `오늘 연락`처럼 상담에만 해당하는 작은 필터와 건수를 둔다. 모든 예정 업무는 독립 메뉴에서만 연다.

### 3-2. 상담 상세 — 고객별 타임라인

상담 상세는 카드 모음이 아니라 한 고객의 진행 과정을 읽는 화면이다.

1. 상단 요약: 고객 식별명, 단계, 담당자, 다음 연락일
2. 희망 조건: 지역, 예산, 방 형태, 입주 희망일
3. 연결 매물: 최초 문의 매물과 제안·관심 매물을 구분
4. 상담 타임라인: 최초 문의, 전화, 문자, 방문, 메모, 상태 변경을 시간순으로 누적
5. 계약 결과: 출처 상담으로 연결된 계약과 실제 계약 매물 요약

- `매물 찾기`는 매물 목록으로 이동하며 상담 조건을 검색 필터로 전달한다.
- 선택한 매물은 상담의 제안 매물로 연결한 뒤 타임라인에 기록한다.
- `계약 생성`은 현재 상담을 출처 상담으로 미리 선택한다. 실제 계약 매물은 사용자가 별도로 고른다.
- 연락처·상세 메모는 현재 재빌드 범위의 화면과 목업 데이터에 표시하거나 입력하지 않는다.

### 3-3. 오늘 예정 업무 — 작고 단순한 보조 화면

인박스는 대시보드가 아니다. 다음 네 종류만 짧은 목록으로 보여 준다.

1. 지연된 상담 다음 연락
2. 오늘 연락할 상담
3. 오늘 또는 임박한 방문·계약·잔금·입주·만기 일정
4. 매물 재확인·사진·현장 확인
5. 퇴실 예정일, 퇴실 확인, 다음 임차인 안내 전 확인

- 항목에는 업무 종류, 대상 이름, 기한, 상태만 표시한다.
- 기본 그룹은 `지연됨`, `오늘`, `이번 주`로 나누고, 업무 종류는 `상담`, `매물`, `퇴실`, `계약`, `확인` 텍스트 배지로 구분한다.
- 항목을 누르면 원래 상담·계약·매물 상세를 연다.
- 완료 체크는 인박스 항목의 확인 여부만 바꾸며 원본의 날짜·상태를 자동 변경하지 않는다.
- 요약 숫자·그래프·최근 매물 표를 중심으로 화면을 구성하지 않는다.

### 3-4. 매물 관리 — 빠른 재고 검색과 비교

매물 관리의 중심은 넓은 표다. 상담 중 조건에 맞는 재고를 빠르게 찾고 서로 비교할 수 있어야 한다.

- 검색: 건물명, 주소, 호실, 매물번호.
- 필터: 상태, 거래 유형, 가격 범위, 입주 조건, 방 형태, 보유처, 사진 보유 여부, 재확인일.
- 기본 열: 상태, 건물·호실, 구조, 가격·관리비, 입주 가능일, 재확인 상태.
- 목록에서 허용하는 빠른 수정: 상태, 사진 보유 여부, 재확인일, 보유처.
- 연락처, 출입 정보, 계좌, 내부 메모는 목록과 인박스에 표시하지 않는다.

상담에서 이동한 경우에는 상담 조건이 필터에 적용된 것을 눈에 보이게 표시하고, `상담으로 돌아가기`와 `이 상담에 제안` 행동을 제공한다.

### 3-5. 건물·호실 — 3단 탐색기

| 왼쪽 | 가운데 | 오른쪽 |
| --- | --- | --- |
| 건물 목록·건물 검색 | 선택 건물의 호실 목록 | 선택 호실의 현재 매물·과거 이력 |

- 건물 목록에는 건물명, 주소, 호실 수를 표시한다.
- 호실 목록에는 호실, 층, 구조, 현재 상태를 표시한다.
- 상세 패널에는 현재 매물의 핵심 조건과 과거 매물 이력을 분리한다.
- 건물·호실의 공통 정보는 이 화면에서 수정한다.
- 연결 상담은 짧은 요약과 링크만 제공하고, 상담 내용 편집은 상담 화면에서 한다.

### 3-6. 계약 관리 — 상담 성과를 실제 계약으로 연결

계약 목록은 일정과 상태 판단이 우선이다. 계약 상세는 단계 이력을 시간순으로 남긴다.

- 목록 열: 계약 상태, 실제 계약 매물, 출처 상담 식별명, 계약일, 입주일, 만료일, 잔금 일정.
- 상세에는 실제 계약 매물과 출처 상담을 반드시 구분해 표시한다.
- 가계약, 정식계약, 잔금 예정, 완료, 해지 단계는 덮어쓰지 않고 누적한다.
- 계약 상태에 따라 매물·상담 상태를 바꾸는 행동은 영향 설명과 확인 창을 거친다.

## 4. 시각 디자인 시스템

전체 인상은 차분하고 집중하기 쉬운 사무 관리 도구로 만든다. 장식보다 정보의 위계와 읽는 속도를 우선한다.

| 항목 | 기준 |
| --- | --- |
| 배경 | 아이보리 `#FAF8F4`. 본문과 표가 편안하게 구분될 정도의 대비 |
| 사이드바 | 연한 스톤 `#F1EDE8`. 어두운 색면을 사용하지 않으며, 선택 메뉴는 `#F3E4DC` 배경과 `#8F4E36` 글자로 표시 |
| 본문·제목 | 읽기 쉬운 산세리프 글꼴. 기본 글자 `#302B28`, 보조 정보 `#7B7470` |
| 숫자·금액·날짜 | 고정 폭 숫자 스타일을 사용해 표의 세로 정렬을 안정적으로 유지 |
| 강조색 | 테라코타 `#A85F43`을 주 행동색으로 사용. 연한 선택 배경은 `#F3E4DC`. `새 상담 등록`, `새 매물 등록` 등 각 페이지의 주 행동 하나에만 적용 |
| 상태 | 색상과 텍스트 배지를 함께 사용. 지연은 `#B94A42`, 오늘·주의는 `#B77A2A`, 완료·안정 상태는 제한적으로 `#69775E`를 사용하고 `지연`, `오늘` 문구를 함께 표시 |
| 표 | 충분한 행 간격, 좌측 정렬 텍스트, 우측 또는 고정 폭 숫자 열. 긴 문장은 두 줄 이상 늘어나지 않게 요약 |
| 카드 | 작은 요약·보조 업무에만 사용. 모든 정보를 카드로 나누어 대시보드처럼 만들지 않음 |
| 여백 | 목록에서 한 화면에 볼 수 있는 행 수를 줄이지 않는 범위에서 통일 |

## 5. 공통 UI와 파일 분리 계획

`app/**/page.tsx`는 화면의 순서와 데이터 연결만 담당한다. 큰 JSX, 저장 처리, 입력 검증, 표 마크업을 한 파일에 몰아넣지 않는다.

| 구분 | 파일 위치 | 공통 또는 화면 전용 부품 |
| --- | --- | --- |
| 기본 UI | `components/ui/` | Button, Input, Select, Dialog, Sheet, Tabs |
| 공통 업무 UI | `components/shared/` | `AppShell`, `SidebarNav`, `PageHeader`, `StatusBadge`, `DataTableFrame`, `EmptyState`, `ErrorState` |
| 상담 전용 | `features/consultations/components/` | `ConsultationList`, `ConsultationFilters`, `ConsultationTimeline`, `ConsultationSummary`, `SuggestedListings`, `ConsultationInboxPanel` |
| 매물 전용 | `features/listings/components/` | `ListingTable`, `ListingFilters`, `ListingQuickEdit`, `ListingPicker`, `BuildingExplorer` |
| 계약 전용 | `features/contracts/components/` | `ContractList`, `ContractFilters`, `ContractTimeline`, `ContractStatusConfirmDialog` |
| 인박스 전용 | `features/tasks/components/` | `TaskInbox`, `TaskGroup`, `TaskCompletionControl` |

- `MetricCard`는 기본 공통 부품으로 만들지 않는다. 업무상 꼭 필요한 작은 수치 요약이 확인된 화면에만 제한적으로 추가한다.
- `FilterPill`은 대시보드용 부품이 아니라, 목록에서 실제로 반복 사용하는 상태·기한 필터일 때만 공통화한다.
- 페이지 전용 컴포넌트가 다른 화면에서도 같은 목적·모양으로 반복될 때에만 `components/shared/`로 옮긴다.

## 6. 구현 순서와 화면 연결

상담이 업무의 중심이더라도, 상담에서 선택할 재고의 최소 기반은 먼저 필요하다. 따라서 개발 순서와 화면의 중요도를 혼동하지 않는다.

1. 공통 앱 셸, 로그인, 빈 상담 화면
2. 최소 건물·호실·매물 데이터 구조와 매물 검색·선택 화면
3. 상담 목록·등록·상세 타임라인·상담 조건으로 매물 찾기·제안 매물 연결
4. 계약 생성·출처 상담 연결·단계 이력
5. 오늘 예정 업무와 완료 체크
6. 광고비·문구·내보내기

각 단계의 완료 뒤에는 `TODO.md`, `CURRENT_IMPLEMENTATION_STATUS.md`, `BUILD_PROGRESS.md`, 필요 시 루트 `README.md`를 함께 갱신한다.

## 7. 데이터 보호와 예외 상태

- 목록·인박스·모바일 카드에는 연락처, 출입 비밀번호, 계좌, 내부 메모를 기본 표시하지 않는다.
- 모든 화면에 로딩, 빈 화면, 오류, 저장 중, 권한 없음, 삭제·상태 변경 확인 창을 준비한다.
- 상태 변경, 계약 완료·해지, 연결 기록 삭제는 결과를 설명하고 사용자가 확인한 뒤 처리한다.
- 가공 데이터만 사용해 정적 UI와 Dev 화면을 확인한다.

## 8. 디자인 구현 완료 기준

- [ ] 로그인 후 상담 관리가 첫 화면으로 열린다.
- [ ] 상담 목록에서 다음 연락·상담 단계를 한눈에 판단할 수 있다.
- [ ] 상담 상세에서 매물 찾기로 이동해 전체 매물 표를 검색하고, 선택한 매물을 다시 상담에 연결할 수 있다.
- [ ] 오늘 예정 업무가 원본 데이터를 중복 관리하지 않고 원래 상세 화면으로 연결한다.
- [ ] 건물·호실 화면이 3단 탐색기로 동작한다.
- [ ] 계약 화면에서 출처 상담과 실제 계약 매물이 구분되어 보인다.
- [ ] 목록, 상세, 인박스에서 민감 정보가 기본적으로 숨겨져 있다.
- [ ] PC와 모바일에서 상담 확인·매물 검색·상세 확인·간단 수정 흐름을 확인했다.
- [ ] 화면별 코드가 공통 UI와 업무별 컴포넌트로 나뉘어 있고, 페이지 파일이 조립 역할만 한다.
