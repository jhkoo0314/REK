# Supabase 데이터 모델

> 새 migration은 이 문서를 기준으로 작성하며, 파일 작성과 Dev 적용을 구분한다.

> P0 열 이름·필수 여부·상태값·검증 규칙의 확정본은 `P0_DATA_FIELD_SPEC.md`를 따른다.

## 공통 규칙

- 기본키는 UUID, 업무 데이터에는 `organization_id`, `created_at`, `updated_at`을 둔다.
- 금액은 만원 단위 정수, 업무 날짜는 `date`, 기록 시각은 `timestamptz`를 쓴다.
- 일반 수정은 현재 매물 행을 `update`한다. 자동으로 새 회차를 만들지 않는다.
- P1 계약 관리에서 계약 상태 또는 계약 단계 이력을 저장하면 `contracts.listing_id`로 연결된 현재 매물을 자동 전환한다. `계약 진행`·`잔금 예정`은 `contract_in_progress`, `계약 완료`는 `contract_complete`·`is_current = false` 과거 이력으로 바꾼다. `해지`·`만료`는 아직 계약 진행인 매물만 `vacant`로 되돌리며, 종료된 과거 이력은 다시 열지 않는다.

## 단계별 테이블

| 단계 | 테이블 | 핵심 내용 |
| --- | --- | --- |
| P0 | organizations, organization_members | 조직, Clerk 사용자 ID, admin/staff, 활성 여부 |
| P0 | buildings | 주소·공통 정보 |
| P0 | units | 호수 정규화, 구조·방향·옵션 |
| P0 | building_contacts | 건물별 제한 연락처와 대표 연락처 표시 |
| P0 | unit_access_details | 호실별 제한 출입 비밀번호·출입 메모 |
| P0 | listings | 매물 표시번호(`M-000001`), 매물 종류, 현재 매물 조건, 가격·입주·사진 보유 여부·재확인·현장 상태·보유처 |
| P1 | consultations, consultation_followups | 일반/매물 상담, 고객 연락처·희망 조건·다음 연락, 전화·문자·방문 후속 이력 |
| P1 | contracts, contract_activities | 실제 계약 매물, 출처 상담, 일정·금액·중개 방식·단계 이력 |
| P1 | task_completions | 계산된 업무의 완료 체크만 저장 |
| P1 | monthly_advertising_costs | 기준연월·채널·월 광고비·메모 |

## 반드시 막을 것

- 같은 조직에서 같은 건물·정규화 호실 중복
- 호실당 현재 매물 두 건
- 다른 조직의 건물·호실·매물·상담·계약 연결
- 음수 금액과 앞뒤가 맞지 않는 날짜
- 같은 기준연월·광고 채널 광고비 중복

## 데이터 관계

```text
조직 → 건물 → 호실 → 현재/과거 매물
                         ├─ 상담 → 후속 이력
                         └─ 계약 → 단계 이력
건물 → 제한 연락처
호실 → 제한 출입 정보
계산된 업무 → 완료 체크
조직 → 월별 광고비
```

사진 파일·매물별 광고 채널 테이블은 이번 재빌드 범위에 넣지 않는다.

## P1 상담 저장 규칙

- `consultations`에는 일반/매물 구분, 최초 문의 매물(일반 상담은 처음에 비워둘 수 있음), 고객 식별명·연락처, 상담일·유입 경로·상담 방식·상담 메모를 저장한다.
- 희망 지역·방 구조는 복수 선택과 기타 직접 입력을 허용하고, 예산·희망 입주일·필수 조건 메모를 함께 저장한다.
- 상담 상태는 `진행 중`, `보류`, `종료`, `확인 필요`로, 진행 단계는 `신규 문의`, `조건 확인`, `방문 예정`, `방문 완료`, `검토 중`, `종료`로 분리한다. `계약 진행`·`계약 완료`는 상담에서 선택하거나 변경할 수 없다.
- `consultation_followups`에는 일자, 방식(전화·문자·방문·기타), 진행 단계, 방문 결과, 종료 사유, 다음 연락일, 메모를 누적한다. 추가·수정·삭제 후 상담의 최신 상담일·마지막 후속 이력·다음 연락·단계 요약을 다시 계산한다.
- 상담을 종료하면 다음 연락일을 비운다. 일반 상담은 후에 최초 문의 매물을 연결할 수 있다.

## 매물 종류 확장 규칙

- `listings.property_type`은 원룸, 투룸, 아파트, 오피스텔, 상가, 사무실을 구분한다. P0 화면에서는 원룸·투룸만 실제 선택·검증한다.
- 방 구조는 주거형 매물에만 적용하며 상가·사무실은 빈값을 허용한다.
- 건물은 복합 용도일 수 있으므로, 매물 종류의 기준은 건물 전체가 아니라 매물에 둔다.
- 아파트 단지·동·공급면적 또는 상가 권리금·부가세·용도처럼 전용 항목은 실제 도입 시 별도 migration으로 추가한다.
