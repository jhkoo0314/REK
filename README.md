# 부동산 매물관리 웹서비스

현재 Streamlit 내부 업무 도구를 웹으로 다시 구현하는 프로젝트입니다. 고객 공개 사이트가 아니라, 사무실 직원이 매물·상담·계약·오늘 할 일을 안전하게 처리하는 로그인 기반 도구입니다. 매물 목록은 기본 현재 매물과 전체 상태·과거 이력 검색을 구분하며, 과거 이력은 읽기 전용으로 확인합니다. 매물 검색은 표시 범위·상태·방 형태를 바로 제공하고, 나머지 조건은 상세 필터에서 확인합니다. 계약 완료 뒤 해지·만료는 계약 이력으로 보존하고, 현재 매물이 없을 때만 새 공실 매물을 자동 생성합니다. 건물·호실 관리에서는 현재 매물이 없는 호실의 최근 조건을 불러와 새 공실 매물을 바로 등록할 수 있습니다.

## 현재 단계

P0 매물 관리와 P1 상담·계약·오늘 할 일의 실제 Dev DB 저장 흐름을 구현하고 확인했습니다. 계약 등록에서는 매물번호·건물명·주소·호수로 실제 계약 매물을 검색하고, 필요할 때 과거 매물 이력도 선택할 수 있습니다. 매물 종료일, 사진 유무·재확인일 제거, 과거 매물 계약 선택, 계약 완료 후 해지·만료 시 새 공실 생성에 관한 4개 변경 파일은 Dev DB에 적용했습니다. 중개수수료 수입·담당자별 매출관리 migration은 Dev DB에 적용했고, 직원별 기본 수수료 비율 migration 적용과 실제 브라우저 확인이 남아 있습니다. Excel·CSV 내보내기는 MVP에서 제공하지 않으며, Production 연결과 실제 업무 데이터 입력은 아직 하지 않습니다. 실제 구현 상태는 `docs/CURRENT_IMPLEMENTATION_STATUS.md`에서 확인합니다.

## 개발 실행

1. `.env.local`에 이미 준비된 Clerk Development 설정을 유지합니다. 값은 Git·화면·로그에 표시하지 않습니다.
2. `npm run dev`를 실행한 뒤 브라우저에서 `http://localhost:3000`을 엽니다.
3. 로그인하면 중요업무알림(`/dashboard`)으로 이동합니다.

## 문서 사용 순서

1. `docs/REBUILD_MASTER_SPEC.md` — 전체 범위·업무 규칙·보안·확정 폴더 구조
2. `docs/TODO.md` — 지금 진행할 작업과 완료 체크
3. `docs/CURRENT_IMPLEMENTATION_STATUS.md` — 실제로 끝난 작업과 확인 결과
4. `docs/BUILD_PROGRESS.md` — 재빌드 판단과 다음 안전한 작업
5. `docs/PROJECT_STRUCTURE_INDEX.md` — 폴더 구조와 업무별 코드 위치
6. `docs/SALES_REVENUE_BUILD_PLAN.md` — 중개수수료 수입·담당자별 매출관리 구현 전 계획

## 중요한 원칙

- 기존 Streamlit SQLite 자료는 자동 이관하지 않는다.
- Dev·Preview에는 가공 데이터만 사용한다.
- DB migration은 파일 작성 뒤 별도 승인으로만 Dev에 적용한다.
- `.env.local`은 Git에 올리거나 화면·로그에 표시하지 않는다.
- 코드와 화면은 기능별 폴더·파일로 나누며, 한 파일에 화면·검증·DB 처리를 몰아넣지 않는다.

## 작업 종료 기록 규칙

각 단계 또는 기능이 끝나면 다음 문서를 함께 갱신합니다.

- `TODO.md`: 실제 완료한 체크 항목
- `CURRENT_IMPLEMENTATION_STATUS.md`: 구현 범위, 검사 결과, 브라우저 확인, DB 적용 여부, 남은 작업
- `BUILD_PROGRESS.md`: 다음 작업과 승인 필요 사항
- `README.md`: 사용자에게 보여 줄 현재 단계와 실행 방식이 바뀐 경우
