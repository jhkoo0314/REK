# 승인 디자인 — 구현 준비 정리

> 기준: `docs/Design_guide/`의 승인된 정적 시안 7종  
> 목적: 디자인 의도를 유지한 채 실제 Next.js 화면과 이후 업무 기능으로 안전하게 연결한다.

---

## 1. 확정된 디자인 방향

- 밝은 회색 배경 위에 흰색 카드·표를 사용하는 **Modern Minimal Luxury** 업무용 화면
- 본문 글꼴은 `Inter`, 금액·날짜·기간 숫자는 `Roboto Mono`를 사용한다.
- 공통 색상은 배경 `#F8FAFC`, 카드 `#FFFFFF`, 경계선 `#E2E8F0`, 주 행동 파랑 `#2563EB`를 기준으로 한다.
- 좌측 고정 사이드바 + 상단 헤더 + 넓은 본문 작업 공간
- 파랑을 주 행동 색상으로 사용하고, 상태는 텍스트가 포함된 둥근 배지로 표시
- 카드 모서리는 넉넉하게 둥글게, 그림자는 약하게 사용
- 숫자·금액은 정렬이 흔들리지 않게 고정 폭 숫자 스타일을 사용
- 표는 업무 판단을 우선하고, 긴 정보·민감 정보는 상세 화면으로 보낸다.
- 모바일에서는 사이드바 대신 메뉴, 넓은 표 대신 핵심 정보 카드 목록을 사용한다.

### 3.1 페이지·컴포넌트 분리 의무 규칙

각 URL의 `page.tsx`는 화면을 조립하는 역할만 한다. 한 페이지 안에 카드, 표, 폼, 필터, 탭의 상세 마크업을 길게 넣지 않는다.

| 구분 | 파일 위치 | 예시 | 사용 기준 |
|---|---|---|---|
| 페이지 조립 | `app/(app)/<url>/page.tsx` | `DashboardPage` | 화면 순서와 데이터 연결만 담당 |
| 업무 전용 부품 | `features/<업무>/components/` | `DashboardHero`, `ListingFilterPanel` | 해당 업무 화면에서만 쓰는 카드·표·폼·섹션 |
| 공통 업무 UI | `components/shared/` | `StatusBadge`, `PageHeader`, `DataTableFrame` | 두 화면 이상에서 동일 목적·형태로 재사용 |
| 기초 UI | `components/ui/` | Button, Input, Dialog | shadcn 기반의 범용 입력·버튼·다이얼로그 |

- 새 페이지를 만들기 전에 먼저 **공통으로 쓸 부품**과 **그 페이지에서만 쓸 부품**을 이 문서에 적는다.
- 상태 배지, 표 틀, 페이지 제목, 민감 정보 접힘 등은 페이지마다 복사하지 않고 공통 부품을 import한다.
- 업무 규칙·가공 데이터·타입도 가능하면 `features/<업무>/` 안에서 관리한다.
- 한 컴포넌트가 두 가지 이상의 명확한 역할을 맡거나 읽기 어려울 만큼 길어지면, 역할별 하위 컴포넌트로 분리한다.

## 4. 화면별 데이터 연결 순서

정적 디자인을 먼저 구현한 뒤 아래 순서로 실제 데이터를 연결한다.

1. 공통 앱 셸과 상태 배지
2. 매물 목록·등록·상세·수정(P0)
3. 대시보드와 오늘 할 일
4. 상담
5. 계약
6. 광고 현황과 문구 템플릿
7. admin 사용자 관리

## 5. 구현 때 지켜야 할 업무 규칙

승인된 시안의 모양은 유지하되, 아래 규칙은 변경하지 않는다.

- 일반 가격·상태·입주일 수정은 기존 현재 매물을 수정한다. 새 매물을 자동 생성하지 않는다.
- 계약 완료·취소는 매물 상태를 자동으로 바꾸지 않고 사용자에게 먼저 확인한다.
- 광고 문구 작성 결과만으로 광고 상태·매물 상태를 자동 변경하지 않는다.
- 연결 기록이 있는 매물은 삭제보다 상태 변경 또는 비활성화를 우선 안내한다.
- 목록에서는 연락처, 계좌, 출입 비밀번호, 내부 메모를 표시하지 않는다.
- 광고 화면의 `AI 카피라이팅` 표기는 실제 기능 구현 시 **광고 문구 템플릿**으로 처리한다. 1차 범위에는 AI 자동 생성 기능을 넣지 않는다.

## 6. 시안과 기존 화면 명세의 조정 기준

| 항목 | 구현 결정 |
|---|---|
| 계약/상담/광고의 SCR 번호 차이 | 번호가 아닌 URL과 기능 목적을 기준으로 구현 |
| 시안의 상담 목록 연락처 열 | 기본 목록에서는 마스킹 또는 숨김, 상세에서만 필요한 범위 표시 |
| 시안의 `매매` 거래 방식 버튼 | 1차 임대 중심 범위에서는 월세·전세·확인 필요로 시작, 확장은 별도 승인 |
| 시안의 엑셀 저장 버튼 | 모양만 먼저 두고 실제 내보내기는 후속 기능으로 연결 |
| 시안의 사용자·환경 설정 메뉴 | admin 전용으로 표시, 실제 관리 기능은 조직·권한 구현 뒤 연결 |
| 시안의 대시보드 수치·샘플 이름 | 실제 데이터 연결 전에는 가공 테스트 데이터만 사용 |

## 7. 정적 UI 빌드 완료 기준

- [ ] 로그인 후 모든 승인 화면으로 이동할 수 있다.
- [ ] 사이드바·헤더·여백·색상·상태 배지가 모든 화면에서 같은 체계로 보인다.
- [ ] 매물 목록, 등록, 상세, 상담, 계약, 광고 시안의 정보 위계가 반영된다.
- [ ] 모바일에서 메뉴, 목록, 핵심 행동이 읽히고 조작 가능하다.
- [ ] 실제 DB 저장 기능 없이도 로딩·빈 화면·권한 없음·오류 상태의 자리가 마련돼 있다.
- [ ] 가공 데이터만 사용하고 민감 정보는 목록에 표시하지 않는다.

## 8. 다음 실제 빌드 단위

**다음 작업: P0 매물 디자인을 실제 Dev DB 기능에 연결할 준비**

승인된 디자인의 목록·3단계 등록·상세 화면은 유지한다. 화면을 새로 디자인하지 않고, 저장에 필요한 입력·상태·안전장치를 현재 카드와 표 안에 추가한다.

### 연결 전 확정할 기준

1. 신규 등록 1단계에는 DB 필수 건물 주소 항목을 빠짐없이 넣는다. 긴 항목은 `상세 주소 정보` 접힘 영역으로 둘 수 있다.
2. 2단계는 호실 선택/신규 등록을 담당한다. 호실 구조와 기본 옵션은 이 단계에서 저장한다.
3. 3단계는 매물 확보처, 매물 상태, 거래 유형, 금액, 입주 가능일, 매물 메모를 저장한다.
4. 월세·전세 선택값은 적용 완료된 `0003` migration의 거래 유형 열에 저장한다. 이미 적용한 `0001`, `0002`, `0003` 파일은 수정하지 않는다.
5. 내부 메모·출입·연락처는 상세 화면에서 기본 접힘으로 유지한다.
6. 상담·계약·광고 탭은 해당 P1 데이터가 만들어질 때까지 실제 건수 대신 준비 중 빈 화면을 표시한다.

### P0 컴포넌트 계획

- 페이지 조립: `app/(app)/listings/page.tsx`, `app/(app)/listings/new/page.tsx`, `app/(app)/listings/[listingId]/page.tsx`, 향후 `app/(app)/listings/[listingId]/edit/page.tsx`
- 페이지 전용: 실제 목록 표/모바일 카드, 검색·필터 패널, 건물·호실 선택 단계, 매물 입력 폼, 상세 정보 섹션, 빠른 수정 창
- 공통 재사용: `AppShell`, `PageHeader`, `StatusBadge`, `SensitiveInfo` 및 새 공통 `DataTableFrame`, 로딩·빈 화면·오류 안내, 확인 Dialog
- 제외 범위: 광고 채널 저장, 상담·계약 저장, AI 자동 생성, 사진·Excel·대량 수정

### 실제 연결 순서

1. 가공 조직·테스트 멤버십·가공 매물 데이터를 준비하고 DB 제약을 확인한다.
2. 활성 조직 멤버를 서버에서 확인하는 공통 함수를 만든다.
3. 매물 목록과 검색·필터를 실제 Dev DB에 연결한다.
4. 건물 → 호실 → 매물 신규 등록과 중복 경고를 연결한다.
5. 상세·전체 수정·목록 빠른 수정을 연결한다. 일반 수정은 언제나 기존 현재 매물 행만 갱신한다.
