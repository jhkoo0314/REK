# 웹 재빌드 진행 현황

> 최종 갱신: 2026-08-26
>
> 기준: `REBUILD_MASTER_SPEC.md`

## 현재 상태

- Streamlit 시스템을 기준으로 웹을 처음부터 다시 구현하기로 결정했다.
- 기존 Next.js 코드·가공 화면·기존 기능 구현은 재사용하지 않는다.
- Clerk·Supabase의 원격 설정, 로컬 `.env.local`, `docs/Design_guide/`, 문서와 Git 이력은 보존한다.
- 기존 로컬 migration과 seed는 재빌드 기준으로 삭제했다. Dev DB의 초기화·새 migration 적용은 아직 승인되지 않았다.
- 기존 Streamlit SQLite 데이터는 읽기 전용으로 보관하며 자동 이관하지 않는다.
- 화면 컨셉을 목록 중심 부동산 업무 CRM으로 확정했다. 상담 관리를 대표 업무 화면과 로그인 후 시작 화면으로, 매물 관리를 상담에 제시할 재고 관리로 정했다.
- 업무 인박스는 대시보드가 아니라 오늘·지연 업무를 원래 상담·계약·매물 기록으로 연결하는 작은 보조 화면으로 정했다.
- 루트 폴더에 Next.js 16·TypeScript·Tailwind 기반과 Clerk Development 로그인·보호된 업무 화면 그룹을 구현했다. Supabase DB는 변경하지 않았다.
- 가공 목업 데이터로 상담 중심 CRM의 주요 화면과 상담 → 매물 검색 → 제안 → 계약 연결 흐름을 구현했다. 실제 저장 기능은 없다.

## 이번 재빌드에서 확인한 사항

- 기존 웹 구현은 매물 P0 일부와 가공 화면이 섞여 있어, Streamlit 기능 기준으로 이어서 확장하면 문서·데이터·화면 기준이 달라질 위험이 있다.
- 따라서 코드만 비우고, 새 기준서와 실행 목록을 먼저 작성한 뒤 P0부터 다시 구현하는 방식이 적절하다.
- Streamlit의 광고 기능은 매물별 광고 상태가 아니라 월별 광고비와 직접입력형·비저장 문구 생성이다.
- 기존 1~13 문서는 이전 구현·축소 MVP·삭제된 migration을 함께 전제하고 있어 재빌드 기준으로 전면 교체했다. 이전 계획 문서 `TASK.md`, `MVP_REBUILD_PLAN.md`, `DEV_DB_SCHEMA_PENDING.md`는 제거했다.

## 다음 안전한 작업

1. 로그인·로그아웃과 모바일 메뉴, 가공 데이터 화면 전환을 브라우저에서 확인하고 공통 오류·저장 중·권한 없음 상태를 보완한다.
2. 사용자 디자인 검토·확정 뒤 P0 데이터 모델을 최종 검토하고 새 migration 파일을 작성한다.
3. 사용자의 별도 승인 후에만 Dev DB 초기화·migration 적용·가공 seed를 실행한다.

## 확인 결과

- 이번 작업에는 루트 Next.js 기반, Clerk Development 로그인, 보호된 업무 화면 그룹, 공통 App Shell 구현이 포함된다.
- DB migration 적용, RLS 변경, 배포, Git push, 실제 데이터 입력은 수행하지 않았다.
